# Motion Worker

这是后续 Python 动作处理服务的接口位置，当前没有生产 Worker。S0 Web 仅使用原创合成演示，不通过此目录生成真实编舞，也未接入 LLM。

## 目标职责

- 接收经过校验的数拍、内容包/Avatar 引用及 ArrangementPlan，按审核模板或有界路径搜索处理整段与单个八拍替换。
- 从获授权的私有存储读取动作和过渡，处理重定向、时间映射、融合与约束，产出不可变 BakedTake。
- 提供来源、文件 hash、资源和 evaluator 版本、接触/衔接检查、替换边界与范围外等价报告。检查失败时不能把候选标成 ready。
- 网页与离线渲染读取同版 BakedTake；教学镜像与慢放属于显示/导出设置。
- 后续接入逐帧渲染和 FFmpeg 固定构图 MP4。实际视频未生成前，不将元数据或占位 artifact 称为导出成功。

## S1 接入顺序

1. 取得 original 2.1.0 ZIP，在私有工作区先读根 `AGENTS.md` 和工程说明，执行原验证。
2. 从原同源生成器引入机器契约、类型及版本规则；为当前 `preview-1` 明确适配或迁移。当前目录不假定与原协议兼容。
3. 接入一个真实合法的小包和一个 Avatar，先验证完整八拍路径及两个非相邻中间槽位替换。
4. 对照原 evaluator 验证插值与时间映射，再验证真实人物、脚接触、替换边界及来源。数学一致性不能替代真实舞蹈审核。
5. 一旦能播放真实组合，立即开始教师观察；保留失败及返工记录。

当前尚未读取 ZIP 内的机器契约、参考 evaluator 或测试，不能引用原工程包的通过数量作为此服务的验证结果。重型任务的身份、版本、租约、取消、幂等与计量也须与生产 API/数据库一起实现。

## 部署边界

普通 Cloudflare Worker 用于轻量 API 与任务入口；Python 动作计算、渲染和 FFmpeg 使用独立执行环境。先测真实 CPU、内存、运行时间和费用，再评估 Cloudflare Containers 或外部 worker。数据库保留规格的 PostgreSQL 默认选择，动作和任务产物置于私有对象存储。

public 仓库只存代码、原创演示和安全的测试数据。不要提交用户音乐、受限动作/Avatar、合同、教师个人资料、原私有工程 ZIP 或其历史附件。

当前无启动或部署命令。实现服务时再加入经过验证的入口、依赖锁定、成功/失败 fixture 与相关运行说明，避免用占位配置假装已部署。
