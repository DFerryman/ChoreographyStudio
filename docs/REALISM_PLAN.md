### 判断依据与当前缺口

两个较好的舞蹈场景主要来自 CMU 真人动捕：复杂街舞 85_12、Salsa 61_08，经固定骨架重定向和明确的源异常／支撑适配，见 [场景来源](SCENE_PACKS.md)。这种真实运动先验包含全身协调和时间关系，不能归因于文本模型输出 JSON。当前文本生成链路虽有骨架层级、肢长、上下文和连续曲线，但没有把解剖关节范围、接触、身体碰撞和完整动力学作为候选采用条件。Structured Output 解决格式，不提供动作真实性。

只读检查上传的复杂街舞：161 个抽样姿态均触发现有保守编辑关节范围，130 个触发身体代理碰撞、20 个触发地板代理碰撞。这说明当前编辑范围、重定向坐标与碰撞代理需要校准；不能据此判断真人动捕全部不可能，也不能为让参考通过而任意放宽范围。现有 Rapier 路径只有一个汇总动态刚体，不能当作带各关节力矩的完整人体动力学。仅检查合法关键姿态也不够，插值中间可能越界。

### 各环节的客观分工

| 环节 | 默认实现 | AI 的实际价值与启用条件 |
| --- | --- | --- |
| 文字意图、风格、动作顺序与空间编排 | 文本 AI 生成结构化编舞计划 | 适合语义理解；优先保留。固定明确指令可直接走确定性路径 |
| 音乐节拍／数拍／起止时间 | 已确认 CountMap；需要时用信号处理 | 不为 BPM、时间换算调用大模型。音乐情绪、段落语义确实影响任务时再评估音频模型，后置 |
| 动作检索与组合 | 特征检索、兼容性评分、曲线适配；AI 可规划选择 | AI 帮助匹配语义或安排新组合；检索已有明确片段不必另发请求，不退回固定六动作 |
| 新动作数据 | 优先真人动捕先验及程序适配；覆盖不足时评估专用动作模型 | 动作训练模型比通用文本模型直接写全身角度更有依据。专用模型的质量仍需实测，不能仅凭品牌保证 |
| 骨架重定向、关节约束、IK、接触与碰撞 | 确定性计算与轨迹求解 | 无需文本 AI 做数值计算。不能靠提示词或逐帧夹紧代替求解器；质量不足则拒绝候选 |
| 支撑识别 | 先由位置、速度、接触几何与来源标记估计 | 多义地板动作可让 AI 提出支撑假设；其置信度不是物理证据，必须经程序核验 |
| 失败修订 | 先用求解器处理小偏差 | 动作顺序、选段或支撑意图需要改变时，再让 AI 根据结构化报告重规划；不让文本 AI反复调单关节数值 |
| 动作语义／风格评估 | 用户预览与固定测试集 | 模型评审仅作可选辅助，需证明比规则有增益；不能自己给自己批准，也不代替人体可行性检测 |
| 最终验收、区间边界、保存与撤销 | 程序负责 | 不调用 AI。任何 AI 输出都不能修改只读边界、降低硬约束或跳过来源检查 |

通用文本 AI、专用动作生成器、确定性算法均为可替换能力。为必要能力固定输入输出，不等于每个能力都要经过一次 AI。首期把“意图与动作选择”合并在一次结构化请求里；不拆成六次昂贵调用。

### 最小契约与闭环

所有产物绑定 schemaVersion、runId、sourceHash／revision、固定 target、骨架／约束 profile 版本、输入产物 ID、生成器来源与预算。程序提供骨架层级、rest／轴／单位、有效原动作、前后上下文、锁定端点姿态及速度、CountMap 和音频元数据；必要性由任务决定，不向模型塞入整份无关场景。支撑未知时明确 unknown，不伪造已有检测结果。

- `ChoreographyPlan`：输入文字意图、数拍和来源明确的动作目录／只读上下文；输出动作段、片段引用或生成意图、时间分配、方向、过渡与接触假设，不携带采用权限。
- `MotionDraft`：输入计划与明确的动作来源；输出统一坐标／骨架的轨迹、接触假设、来源。密集动作与稀疏曲线分别标明，不把低帧关键姿态当作高质量动捕。
- `FeasibilityReport`：程序输入校准后轨迹与身体 profile；输出每项违规的时间窗、关节／碰撞对、测量值、阈值、接缝与检测覆盖、求解状态。检测失败或覆盖不足不得写成通过。
- `RepairPlan`：仅在程序修订不足且确有语义问题时，把报告、原意图和可写域交给 AI；输出新的选段／顺序／接触意图或受限内部修订。不能修改 sourceHash、目标边界、身体参数或硬阈值。任何修订都使相关旧验收失效并重新计算。

流程为：明确生成操作 → 必要的 AI 规划／动作来源 → 程序适配与离线整段求解 → 程序验收 → 合格候选预览／明确采用。失败先尝试有界数值求解；只有需要重新规划才走预算内 AI 修订，再重新验收。预算耗尽、来源变化、取消、不可行或结果不完整均停止，保留原稿。播放只读取冻结曲线，不在 RAF 中夹紧关节、投影碰撞或调用模型。

初期设计上限为每次明确生成最多一次规划请求、按需一次修订请求；这是待实现的应用预算，并非现有 provider 的账户费用硬限额。保留当前 AI 2/min/IP、API 20/min/IP；同时限制 tokens、总时长和取消状态。不排队自动重试，不在限流后循环等待调用。专用动作后端接入前另行定义总预算，不能从这个文本请求额度推导无限生成。

### 约束必须先校准，范围与验收必须分开

按实际 rig 校准功能关节轴、活动范围、身体代理与接触容差；MHR 与 Quaternius 各有版本化身体 profile。固定肢长只是起点，不能说明体重、惯量、摩擦、力量与支撑全部已生效。不能由 AI 编造身体参数，也不能把人工编辑 envelope 直接升级为临床人体范围。

轨迹求解检查整段插值，包含关节耦合、速度／加速度、身体碰撞、地面穿插、支撑点滑移和区间接缝。脚、手、膝、躯干接触与腾空分别建模；不把所有舞蹈强制站立或质心始终处于双脚内。离线自适应采样／可用的曲线极值检查应记录覆盖与误差；有限采样不是连续数学证明。对跳跃、旋转和倒置，需独立的动力学一致性验证，现有单刚体工具不能兑现完整物理成立。

选区外和两个端点保持原有效动作；内部可求解。若原端点在校准 profile 下不可行，或固定时长内没有可行过渡，明确拒绝并建议用户另选区间，不偷偷移动端点或改原场景。物理通过、自然协调、文字语义与数拍契合各自报告，不把其中一项替代其它项。

主界面现在使用新的 [直接动作协议 `ai-motion-1`](../packages/core/src/aiMotion.ts) 和 `/api/motion/generate`，由文本模型输出实际 Root 位置与关节稀疏关键姿态，再在本机编译为连续动画。模型输出局部 Euler XYZ 度数，由程序转换为父节点局部 XYZW 四元数；省略的关节继承前一个生成姿态，起点继承精确原姿态。每个候选记录真实 `cloudflare-workers-ai` provider、模型名、请求 ID、来源 SHA-256 和固定目标，不将新动作伪装为旧 `synthetic-demo` 资产。旧六动作 `/api/choreography/generate` 仅保留兼容入口，主界面不会将新生成失败回退为六种模板。

### 已实现的必要上下文与预算

[浏览器上下文组装](../apps/web/src/aiMotionContext.ts)在首次异步读取前捕获来源与目标，冻结最终请求，发送以下内容；完整 Take、manual、场景和音频字节继续留在本机。

| 上下文 | 当前实现 |
| --- | --- |
| 身份与来源 | 唯一请求 ID、场景 ID、revision、来源 SHA-256；摘要覆盖原 Take、manual、已有 AI 层、完整 CountMap 和所用音频元数据/文件哈希。另以轻量本机来源标记在请求完成及预览/采用时检查过期 |
| 目标 | 发起时固定整段或区间的实际秒数；之后移动选区不会改变这个候选的目标。来源变更、撤销/重做或换场景使旧候选失效 |
| 骨架 | 复用 `neutral-rig-2` 的 25 关节名称、父子层级、固定 offset 与 rest 旋转；米制、右手坐标、Y 向上、Z 向前，Root 是含髋部高度的世界位置 |
| 数拍 | 完整已确认 CountMap、BPM、舞蹈数拍比例、八拍数量、精确 onset 与结尾秒数；数拍不随音轨移动而平移 |
| 原动作 | 当前权威 `take` 连续采样后叠加已采用 AI 层；旧 manual 作为来源身份保留，不再次烘焙覆盖当前 Take。局部区间前后各最多约 1 秒，每侧 4 个稀疏样本，边缘截到场景范围 |
| 精确边界 | 两端完整姿态，按实际时间间隔的单侧数值差分计算 Root 线速度及关节局部旋转的 body-frame 角速度；共享 FK 计算左右脚世界位置/速度。支撑仍为 `unknown`、置信度 0，不根据脚的高度擅自推断接触 |
| 音频 | 主轨和附轨名称、文件 SHA-256、完整音频时长、scene offset、source offset、有效覆盖、静音与缺失标记；主轨映射为 `sourceOffset + sceneTime - audioOffset`，附轨映射为 `sceneTime - trackOffset`。Blob 哈希顺序计算并缓存，不上传音频字节 |
| 结束与预算 | 整段从精确初始姿态开始、最终保持；最多 48 个模型关键姿态，描述最多 2,000 字符，请求 64 KiB、结果 96 KiB、输出上限 8,192 tokens。截断、重复键、无效数值、未知骨骼或越界输出拒绝 |

相邻四元数按较短路径衔接；整圈旋转需要模型提供中间姿态，单独 0°→360° 不能表达完整转圈。系统提示已明确该表示约定，它不是关节限位。

当前新动作默认采用 Workers AI 的 GPT-OSS120B，使用正确的 Chat Completions Schema 包装和 low 推理设置；原 Qwen 已保存动作层保留原模型标注，旧六动作接口仍仅兼容，不是新模型的自动回退。GPT-OSS 首次受控实测现通过基本动作：8个模型关键姿态、抬左臂45°／转头15°，实际舞台12观测与曲线一致，原稿／音乐保持。连续插值有约3.333°超调，不能据此宣称保持角度精确或自然复杂编舞已完成；精确发布、CI与失败历史见验证／部署记录。

首次真实复杂 Schema 输出合法却全部静止，不能以格式验收替代动作语义。该轮先用同 Qwen 切为 JSON 对象模式并把完整 Schema 写入可信提示、保留严格验证；提示补充骨架轴向与一个非零局部角度格式例，不提供整段模板。候选增加近静止提醒；实际运动幅度由后续真实收据验证。第二次 Qwen 调用未通过结构校验，此后转为 GPT-OSS120B；失败不证明 Schema 解码器有缺陷或所有文本模型无法生成动作。

当前 `audioUnderstanding: false`：这个文本模型听不到音乐，不分析音频或混音；它可参考已确认的数拍和用户文字。音频配置用于解释来源及防止旧候选误用，不能称为音乐到动作。缺音可继续纯文本生成，未知完整音频时长不会伪造成已测值。字节与 token 上限是资源边界，不表示每次调用都能完整生成长场景或用完 48 个姿态。

### 原稿保持、曲线与接缝

[独立 AI 动作层](../packages/core/src/aiMotionTrack.ts)存于 `SceneSnapshot.aiMotion`，保留原 Take 的显式非均匀时间戳、原姿态、manual 和其它作者数据。局部修改的可写域严格是 `(startSeconds, endSeconds)`：模型只能返回内部关键姿态，两端由程序从请求对应的原有效动作注入，端点及全部区间外继续调用前一层有效求值器。内部衔接不会重采样或调整邻区旧曲线，普通播放也不会加入强制碰撞投影、关节限制或脚锁。

Root 用匹配两端位置与线速度的 Hermite 曲线；旋转用 SO(3) 对数/指数坐标与角速度切线构造连续曲线，避免把简单逐段 SLERP 当作角速度连续。边界导数为原动作可用一侧的数值估计，不承诺精确恢复所有高阶导数；原动作自身已有关键点速度折线、跳变或导数不唯一时，保留它而不暗中修复区间外。这里保证的区间保持、格式和接缝约束，与加速度连续、脚底接触、动作语义及自然舞蹈质量分开。

每条 AI 轨道最多 12 层，新的局部候选保留前层，整段生成替换已有 AI 层并从固定初始姿态到新结尾平稳保持。采用不会清空原 Take/manual；模型层使用独立来源字段。历史中的原稿和本机音频继续可恢复。恢复/导入时除轨道形状、数拍绑定、数值与层数限制外，还核对局部层两端的保存姿态和速度与前层原稿是否一致，防止篡改接缝绕过候选约束；整段层只固定初始姿态，初始速度可来自被替换的 AI 层，因为时间 0 前没有需要保持的场景区间。整段最终零速度保持仍强制验证。

编译后的曲线另有有界只读诊断：按 30 fps 加精确关键姿态采样，计算相邻位移/转角、速度与加速度，非有限结果拒绝，较急变化提示先预览。它不会投影、夹紧或改写源动作，也不是人体质量评分；有限采样不能证明采样间没有尖峰，更不能证明跟拍、稳定接触或自然编舞。

### 明确候选工作流与本机保存

[主界面](../apps/web/src/App.tsx)把描述、固定目标、生成、候选、预览和采用连接起来。候选在 Timeline 附近展示其实际整段/区间范围；预览和“返回原稿”只是临时展示，只有“采用候选”才写入一次可撤销历史。关闭、取消、过期或失败不采用；整段覆盖已有作者动作保留原有确认流程。保持人物手工创作工具移除和实时场景时钟采样，不重新增加关节参数面板。

新层随本机 IndexedDB、JSON 场景备份及含原音乐的完整 `.choreo` bundle 保存/恢复；原音频 bytes 与 hash 保持原文件，旧场景没有 `aiMotion` 时沿用旧格式语义。相机和音轨仍为独立数据，区间采用不改 CountMap 或音轨位置。客户端按本机来源检查候选过期，Worker 严格验证固定目标与来源摘要的格式并自行回填请求元数据；Worker 不持有完整原场景，不能独立重算本机原稿 SHA。正常加载、播放、取消或回归测试不自动推理，生成只由明确操作发起，没有自动重试、服务端场景/音频存储或数据库写入，沿用低频率限制。

文本模型现在具有直接生成新动作数据的输出空间，但 Structured Output 只能保证协议形状；足够上下文与数学曲线不保证动作顺序正确、符合人体、脚不滑或优美。实际动作质量仍需少量真实候选与人工预览，不能宣称“完美接上”或已优于专用动作模型。

## 2026-10-13 · 优先生成真实动作数据，评估指定帧区间二次编辑

HY输出的FBX含动画数据，本身可二次编辑。应用层未来可把选中帧区间换算成秒，生成等长候选，重定向到现有25关节后只替换该区间并处理两端过渡；区间外作者数据保持，候选明确采用前不改原稿。例如30fps下120→240帧对应4→8秒的4秒片段。该流程需要本项目实现，模型没有读取原动作上下文，不能据此保证接缝自然或完整动作一致性。

[DeepMotion官方SayMotion REST API](https://github.com/DeepMotion/SayMotion-REST-API)确有区间重生成：使用原`t2m_rid`/`variant_id`，提交`inPaintingRequest`中的描述及`intervals[{start,end}]`；它更贴近生成后再次指定区间修改的需求。当前只确认基于该服务原有任务的编辑能力，未确认任意外部FBX或.choreo可直接上传做同样编辑，也未验证区间单位、边界质量或区间外逐值保持。[官方准入页](https://www.deepmotion.com/saymotion-api)要求获批合作伙伴API访问，不能当作无需申请即可调用的现成接口。

阶段选择：易接入的文本生成骨骼片段可先评估腾讯托管HY-Motion；如果模型原生区间二次编辑是硬要求，则优先评估SayMotion或可部署的motion-inpainting模型。音乐到动作的EDGE路线仍为备选，但音乐理解已不是本轮接入前置条件。这里只核对公开文档，没有模型推理、付费开通、账户变更、程序部署或场景数据修改。

当前 [Worker](../apps/api/src/index.ts)已经使用 `response_format: json_schema`，但系统提示禁止骨骼及新动作 ID，[动作协议和候选构建](../packages/core/src/aiChoreography.ts)仅允许六种 `actionId/amplitude` 并调用 `bakePlan`。因此需新建直接表达 Root 与骨骼关键姿态/轨迹的协议和执行器，而不是仅添加 Structured Output 或换模型。JSON/Schema 合法不等于人体动作自然；[Cloudflare JSON Mode](https://developers.cloudflare.com/workers-ai/features/json-mode/)也说明复杂任务可能不能满足 schema，需处理失败，不能静默返回固定模板。

现有骨架是 25 个骨骼、父节点局部 XYZW 四元数、Root 米制位置、Y 向上；[Take](../packages/core/src/motion-types.ts)使用显式时间戳，可能非均匀。先生成稀疏关键姿态或控制曲线，再插值成连续动画；可用明确角度约定降低模型数字难度，由程序转换旋转。60 秒 × 30 fps × (Root 3 + 25 × 四元数 4) 约需 185,400 个数值（未计端点与字段），不能直接塞入当前最多 4,096 output tokens、16 KiB 结果限制。[当前 Qwen 模型](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/)上下文为 32,768 tokens。原型可先验证 2–4 秒短动作，关键姿态密度、稀疏通道与有界请求/输出预算需随新协议核实；长场景按动作阶段分段并共享边界状态，不能把分段成本当作单次完整生成质量保证。

区间设计与验收要求：

- 请求声明骨架/协议版本、原 Take 指纹、CountMap 版本和精确目标起止时间；模型返回内部关键姿态，不获得写入原场景的权限。若等待期间场景改变，候选作废或重新人工发起。
- 初始建议前后各约 1 秒上下文，可按 0.5–2 秒或完整转身/跳跃阶段调整，属于待验证的工程起点。远处可稀疏采样和文字归纳，紧邻边界必须保留原始精确姿态与时间，不能只给动作名称。
- 提供两端 Root 位置/速度、身体朝向/角速度、主要关节的变化趋势及脚支撑状态。导数估计使用实际时间戳和边界外单侧采样；原片段本身不光滑时不宣称其导数唯一或整段已顺滑。
- 由程序锁定两端姿态及全部区间外数据，拒绝越界输出。区间外继续调用原动作求值器，以免改变相邻关键帧、切线或重采样而影响原曲线。只有显式采用后替换区间内部，并作为一次可撤销历史。
- 接缝处理全部在可写区间内部：Root 可使用匹配端点速度的 Hermite 曲线，旋转使用适合旋转空间的连续曲线；除姿态连续外，还检查线速度和角速度。不能把逐段 SLERP 或简单淡入淡出等同于速度无跳变；可再检查加速度尖峰。
- 目标动作与固定边界冲突、选区过短或输出突变时拒绝候选或降低内部动作幅度，不能偷偷改变只读两头。保留顺滑/原动作优先，不在播放时重新强制碰撞、关节投影或锁脚。
- 验收分别检查格式/骨架、区间外精确一致（含非原样本时刻）、接缝姿态/速度误差、内部突变和人工动作质量。优先少量挥手、下蹲起身、转身抬臂及一段原动作局部修改，自动回归默认 mock。区间外不变可做成确定保证，边界连续可做数学约束，自然舞蹈仍须真实候选验证，不能承诺“上下文足够就完美接上”。

## 为什么不直接让物理引擎接管人物

运动学身体按给定轨迹移动，不受重力或接触力自动纠正，也可能穿墙或穿地；需要显式碰撞查询和目标修正。动态刚体受力，但整套人体只加重力和关节连接会倒下，还需主动驱动和平衡控制。因此，加载引擎不等于获得真实编舞。[Rapier 刚体类型](https://rapier.rs/docs/user_guides/javascript/rigid_body_type/)及[场景查询](https://rapier.rs/docs/user_guides/javascript/scene_queries/)支持这一技术区分；选用辅助检查层是本项目的工程判断。

体重只是总质量。质心需要各肢段的质量分布和局部质心；转动和落地还涉及惯量、速度、接触、摩擦及驱动力上限。质心也不能用 Root 或关节点平均替代。[Unity centerOfMass](https://docs.unity3d.com/ScriptReference/Rigidbody-centerOfMass.html)与[inertiaTensor](https://docs.unity3d.com/ScriptReference/Rigidbody-inertiaTensor.html)明确区分质心与惯量。静态重心投影可辅助判断站姿；动态平衡还取决于动量、加速度及接触力，不能将“投影离开支撑面”作为所有舞步的硬拒绝规则。[MIT 接触与平衡建模](https://underactuated.mit.edu/humanoids.html)讨论了质心动力学、摩擦和压力中心。

静态重心投影只提示准静态姿态的支撑风险。动态/腾空状态明确不使用站姿判据硬拒绝，继续检查穿地与身体代理穿插。代理诊断不是皮肤级碰撞，也不单独证明动作安全或可教学。

## Workers AI 的实际范围与零推理验证

用户选择 Workers AI 后，本轮服务端接入 [Qwen3-30B-A3B FP8](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/)，原始 [Qwen 模型卡](https://huggingface.co/Qwen/Qwen3-30B-A3B)为 Apache-2.0。AI 输出受 JSON schema 与业务校验双重限制：在现有六种原创动作模板中选择/排序，控制幅度并给出简短说明；客户端在固定 CountMap 下生成局部关节受限的候选，再由用户明确采用。它是编排助手，不是动作捕捉、任意文本到真实舞蹈的模型，也未获教师认可。原预览 Take 继续如实标识 `synthetic-demo`，另保留 AI 编排来源。

请求只包含舞步描述和已确认节拍摘要，不上传音乐或完整作品；同源 JSON 请求受大小、超时和原生限频保护，没有自动重试、自动云保存或 D1。用户的**不要实际使用 AI 测试、不走量**是本轮硬约束：本地使用 mock/fixture，公网检查不能点真实生成按钮或调用生成端点；真实模型的内容质量、服务响应和推理费用未实测，不能以模拟成功代替真实推理验收。

## 分阶段实现与退出条件

1. **共用运动学与接触诊断。** 将现有 25 关节的父子链、静止偏移和正向求值统一供渲染、IK 与检测使用；校准脚底面、脚掌宽度及身体代理。脚尖/脚跟标记中心不是脚底，不能直接当作地面接触点。平地先用简单几何；复杂场景或动力预览再评估 Rapier。用站立、蹲起、单脚支撑、移步、转脚与跳跃正反例检查穿地、滑脚、身体穿插和接触切换，记录容差依据及关键帧之间的采样覆盖。
2. **当前帧有限 IK。** 优先腿部两段 IK，随后手臂；拖目标形成关节草稿，保持骨长、屈曲方向和活动范围。目标不可达时显示残差，不拉长骨骼或强行扭曲。明确 K 后提交受影响轨，取消、Undo、重开及备份保留原稿。目标初期仅为临时编辑控制。[Unity Two Bone IK](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.2/manual/constraints/TwoBoneIKConstraint.html)的末端目标和弯曲提示是可借鉴的控制方式。
3. **接触区间与支撑反馈。** 当前v12保存明确左右脚、起止帧、固定世界锚点及脚部朝向，平滑进出锁足并在区间外释放。转脚轨迹、脚掌/脚尖支撑切换、自动起跳释放和落地接触重建为后续目标，尚未实现。持久约束版本化并进入 Snapshot、共享历史及完整备份；旧场景缺省为无约束，不自动修复。确定性求解须保持原 CountMap、精确末样本和权威 Take 的一致性。不能盲目逐帧写20轨完整K，否则会触及现有4096键上限；设计同时遵守6001显式样本上限。
4. **可选物理辅助与动力预览。** 先用过滤相邻骨段的碰撞代理进行只读检查；再验证固定步长、检查点恢复和动态跳跃/落地预览。模拟结果保留与原稿的差异，明确采用后固化为新 Take，不能在播放或拖时间线时偷偷改作者的姿态。[Rapier 确定性](https://rapier.rs/docs/user_guides/javascript/determinism/)依赖版本、初值、创建顺序与步数等前提，须实际验证复现和保存恢复。

界面保持简洁：目标操作随选中的手/脚出现，诊断使用一个按需展开入口；不增加一排IK、质量、摩擦和引擎参数常驻按钮。当前AI编排候选自动校验结构并应用关节限位，接触/穿插诊断与物理候选由用户按需查看或运行，尚无自动物理验收。后续AI动作来源同样应通过连续轨迹可行性检查；自然舞蹈还需要可靠动作参考、节奏/重心转移和教师试跳，几何或物理检查不单独构成可教学证明。

## 教师用少量关键姿态编舞

2026-10-08 用户进一步明确主流程：教师自由选择少量关键时刻，在这些时刻摆人物并明确写 K，编辑器自动生成中间过渡。现有稀疏轨已支持这一方式：局部四元数最短路径 SLERP、Root 线性插值，时间线同帧多轨合并为一个关键时刻；无需逐帧写姿态，也无需调用 AI。帧/秒输入和进度定位受固定 CountMap、30 fps 和精确末时刻约束，未写端点由原基底补齐，未写草稿不会成为动画。

IK 负责方便摆关键姿态，脚锁负责明确区间的支撑，质量/碰撞与重力辅助检查过渡中的风险；不能只检查几个键的静态姿态后宣布整段动作真实。接触区间求解补充播放样本，保留少量作者 K。当前 SLERP/线性插值保证连续过渡的基本计算，不提供速度曲线/缓入缓出/自动自然动作设计，也不单独保证脚滑、身体碰撞或动态平衡全部解决。

用户最新要求已将时间点和 K 的图形化组织纳入本轮：舞台正下方一个时间轴合并播放、帧/秒、跳 K、筛选、主添加/更新完整姿态与撤回草稿，v12/v13侧栏只调整/复用姿态；v14已移除精细参数面板并将复用并入时间轴；单轨 K、删除/站姿、移动复制和键明细按需展开，合并重复进度和写 K 入口。选空白时刻或菱形本身不写 K，显式主按钮才完整提交，快捷键按原工具语义。本轮实现与桌面/390 px流程已有本地、单轮线上与完整源码CI通过回执。键标记拖动、缓入缓出或曲线仍是后续，当前没有自动迈步。验证包含少量不均匀姿态时刻、同帧更新、中间过渡、显式 K 不膨胀、删除后重新插值、撤销和保存恢复一致。

## 下一阶段优先：Root 移动的自动迈步辅助 · 尚未实现

2026-10-08 用户提出：人物侧向移动不能双脚滑着走，教师也不应为每次整体位移逐一手 K 两脚。当前 v12 的 Root 插值、IK、脚锁与重力候选**没有自动规划迈步**；不能把它们描述为已经自动解决这一编辑负担。双脚一直锁定时大幅移远 Root 也可能不可达，保持骨长后的残差必须如实展示。

优先增加确定性的程序化迈步辅助，无需为基础步态调用 AI：教师给出目标位置、到达数拍/时刻及可选路径，规划器在所选区间根据距离、方向、用时和人物尺度选择侧步、并步或合适的交叉步，形成支撑脚/摆动脚切换。支撑期保持世界足接触，摆动期释放锁并生成有离地间隙的抬脚、落脚轨迹，再由固定骨长 IK、关节限位和代理碰撞检查求值；可按需用物理候选补充诊断。抬脚、落地和重心过渡必须随数拍安排，不能只把脚沿地面平移，或把整段始终当站姿检查。

使用默认 `neutral-adult-v2` 的固定骨架及脚底代理。平脚落地须由 Foot 的世界朝向和局部脚底平面求脚踝目标：脚底相对踝下移 0.082 米，宽 ±0.048 米、Z 范围 −0.075 至 0.165 米；平脚在地面时踝高约 0.082 米，Toe/Heel 标记中心不是地面。转脚、脚尖或脚跟支撑需要对应接触点/朝向规则，不能把固定脚踝高度硬套所有姿态。规划需检查最大可达、步间干涉与接触切换，不能延长骨骼。

教师创作的上半身旋转、动作节奏和所选区间外原稿优先保留；明确手动足部姿态 K 和脚锁优先于自动规划。规划发现冲突时展示具体区间与可选处理，不暗中覆盖教师的脚部动作。目标太远或到达时间太短时，建议增加步数、给出更充足数拍或缩短位移，由教师选择；不能以滑脚、极限扭关节或自动扩展音乐时长掩盖失败。

生成结果应是可编辑接触/步伐参数和权威 Take 的预览候选，绑定场景、CountMap、所选时间区间与作品/手动序列版本；明确采用后才提交一次共享历史，取消、Undo、场景重开和完整备份保留原稿与来源。求值仍保留 CountMap、原显式时刻及精确末样本，并遵守 4096 轨键/6001 样本上限，不逐帧向每条轨塞 K。播放和拖时间线只消费已经采用的动画，不自动运行规划器或改写权威作品。

程序化迈步如实保留合成来源，并区别教师显式 K、AI 编排和物理辅助来源；不称为动作捕捉或真实舞者动作。退出条件包括左右横移、并步、交叉步与转向、短距离停步、无法按时到达的失败反馈、支撑脚稳定和摆动脚离地、上半身/区间外保留、手动足部优先、版本竞态/取消、历史和备份一致。自然舞步及可教学体验仍需教师试跳、目标设备和连续轨迹验证，程序化或物理通过不替代这些证据。本项列为下一阶段优先工作，v12 当前发布不预记已实现。
