# P1 手动关键帧规则

本轮在原创合成骨架上实现本机手 K。此设计是 `preview-1` 的编辑扩展，不等于 original 2.1.0 的已验证协议；不包含 IK、骨长修改、真实动作质量复检或教学 MP4。

## 操作和空间

一个场景的已确认 CountMap 决定完整动作时长，不拖动或裁剪音乐/八拍。编辑时间用动作内相对时间，以 30 fps 的整数帧定位。最后一帧为 `ceil(duration × 30)`，其时间固定为精确结束时刻；不能把短末帧扩到音乐范围外。

19 个具有可见方向或子骨骼的节点可编辑父相对局部旋转。6 个手指尖、脚尖、脚跟末端节点保留选中和坐标观察，不编辑其不可见旋转。Root 平移独立于 Hips 旋转；骨长、父子层级和静态局部偏移不变。空间继续采用右手系、Y 向上、人物 +Z 向前、XZ 地面和米单位。

数值输入为 intrinsic XYZ 欧拉角（度，每轴 −180 至 180）；持久化为归一化 XYZW 四元数。Root 数值为世界位置，X/Z 在 −5 至 5 米、Y 在 0 至 3 米，仅是本轮场景操作范围，不是人体关节或接触质量约束。

视口操作环在未镜像、暂停的编辑模式下围绕选中关节，以 local 空间旋转；拖动操作环暂停相机操作，空白处仍可导航相机。镜像仅用于观察，不从镜像空间写入动作。

## 草稿、提交与历史

滑条、数值或操作环先改变当前帧的完整 Pose 草稿，舞台即时预览。切换同一帧的选中关节可继续摆姿态。草稿不能被当成已写入的关键帧、权威动画或已保存场景。

用户显式写入当前关节、Root 位移或完整姿态。同轨同帧写入为更新，不产生重复键；完整姿态一次写入 19 个旋转和 Root，成为一个撤销条目。界面的删除操作移除当前帧的所有显式轨键；单轨删除当前仅提供 core API。每次正式动作修改生成新动画 ID、增加作品 revision，并清空旧版本的预览确认；旧候选不可覆盖新动作。

跳帧、播放、切换场景/编辑模式、撤销、改音乐或生成模板前，未写入草稿须明确选择写入后继续、放弃或取消。场景保存也经过这一处理；存储事务失败不显示保存成功，当前修改仍可继续编辑。

沿用每场景 12 步历史，不另建与编排分离的撤销栈。相机、镜像、关节选择不修改权威动画，也不触发重新烘焙。

## 动画数据与插值

每个 Snapshot 可选保存 `manual: KeyframeSequence`，包含 `schema: manual-keyframes-1`、固定 `fps: 30`、不可变 `baseTake`、按关节的稀疏旋转轨和独立 Root 位置轨。键记录整数 frame；输出仍为 `BakedTake`，播放、观察和 JSON 备份消费同一权威产物。

有显式键的轨以基底在 0 和精确结束时刻的姿态作为隐式端点，用户写入端点时替代该端点。相邻旋转键最短路径 SLERP，相邻 Root 键线性插值；这会影响相邻键之间的整段该轨，不宣称只改当前帧或选中八拍。未编辑轨继续使用原基底样本。删除最后一个显式键后，该轨回到基底；全部键删除后保留原始 poses/times，只生成新的动画版本。

烘焙保留基底的显式时间数组、八拍边界与精确末样本，同时加入显式键时刻。不能由 plan 再次生成 base，也不能把已编辑输出不断叠成旧轨的新基底。有限数、合法节点、整数帧、非零四元数、资源边界必须在编辑入口校验；整个序列最多 4096 个轨键，输入与输出都最多 6001 个显式样本，超限明确拒绝。

“从站姿开始”在同一音乐/CountMap/场景下建立中立原始姿态，方便用户构建自己的序列；清空已有手 K 的操作可撤销。模板重新生成清空手 K；采用八拍替换直接消费候选的权威 take，将当前可见动画固化为下一次编辑的基底、清空旧可编辑轨，须明确提示且可撤销。范围外不变仍按替换的权威动画检查，不能保留旧轨再次覆盖新基底。

## 保存与兼容

编辑序列、基底、权威 take 与历史作为 SceneDocument.project 一起由 IndexedDB 事务保存，原音频仍单独包含在同场景。viewer 可选新增 editorMode；旧 `choreo-scene-1` 无该字段或 Snapshot 无 manual 时按已有动作恢复，不重烘焙旧 plan，不替换原音频。

音乐或 CountMap 发生改变时旧手 K 不自动套到新时长。JSON 备份包含正式编辑序列与权威结果，未提交草稿不假装保存成功；JSON 当前尚无导入 UI，原音乐需另行保留。

编辑、播放、烘焙和保存均在浏览器本机运行，无业务 API 调用、自动云保存或 D1 写入。验收优先本地数学/交互测试，正式部署只做一次必要的公网流程验证，继续保留已配置的原生 API 限频。
