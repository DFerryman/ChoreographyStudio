## 教师选择少量关键姿态的主要工作流

2026-10-08 用户追加：教师可以自由选择几个关键时刻，只在这些时刻摆人物、写 K；其间动作由编辑器自动插值，不要求逐帧手摆，也不要求先使用 AI。这里的自由选择是在已确认 CountMap 的固定动作范围内；时间定位仍吸附到 30 fps，保留精确末帧，不改变音乐/场景时长。

现有稀疏核心已支持少量姿态之间自动过渡；本轮按用户进一步要求将操作集中到舞台正下方的统一时间轴，本轮交互与发布已验证。教师先按需「从站姿开始」建立中立基底，在时间轴选择空白时刻或填帧/秒定位，用关节旋转或手脚 IK 摆姿，再在同一时间轴添加完整关键帧，然后选择下一时刻继续。教师只需决定关键姿态及其时间；相邻局部旋转自动最短路径 SLERP，Root 自动线性插值。完整姿态一次写 19 条旋转和 Root，但同一帧合并为一个关键时刻；中间播放样本不冒充新 K。未写起止时刻采用原基底隐式端点；需要自己的首姿到末姿时须明确写入对应端点。

当前时间线可拖进度定位、点击已有 K 标记跳转、按上一个/下一个 K 导航，支持全部/所选关节/Root 查看；当前帧全姿或单轨 K 可删除，键时刻可通过现有「移动与复制关键帧」调整。选时刻或跳帧本身不写 K，草稿仍需写入/放弃/取消。脚锁按已明确的接触区间处理插值后的姿态；没有脚锁时自动插值不等于接触或动力学自动保证。

## 操作和空间

一个场景的已确认 CountMap 决定完整动作时长，不拖动或裁剪音乐/八拍。编辑时间用动作内相对时间，以 30 fps 的整数帧定位。最后一帧为 `ceil(duration × 30)`，其时间固定为精确结束时刻；不能把短末帧扩到音乐范围外。

19 个具有可见方向或子骨骼的节点可编辑父相对局部旋转。6 个手指尖、脚尖、脚跟末端节点保留选中和坐标观察，不编辑其不可见旋转。Root 平移独立于 Hips 旋转；骨长、父子层级和静态局部偏移不变。空间继续采用右手系、Y 向上、人物 +Z 向前、XZ 地面和米单位。

数值输入为intrinsic XYZ欧拉角，持久化为归一化XYZW四元数。v11按所选关节限制数值，v13按用户新增作者优先规则允许各轴有限±180°的明确创作输入；滑条和舞台拖动/IK仍使用人体建议范围。超限姿态提示后保留，写K不再次投影。Root世界位置X/Z在−5至5米、Y在0至3米，仅是场景操作范围，不是接触或平衡约束。

限位不在加载、播放、保存、撤销、删除或键转移时自动改写旧作品。旧超限姿态保留并提示；Root-only 编辑或写 K 不修复其他关节。只写当前关节 K 时限制该关节；写完整姿态时限制全部可编辑关节。正式写 K 之前仍为可撤回草稿，六个只读末端保留。新姿态合法不证明相邻键之间全部 SLERP 都符合接触、解剖或动力学条件。

上述 v11 限位在当轮没有 IK、脚锁、碰撞、分段质量/质心或重力；后续用户授权的 v12 扩展见下节。方案、内置参数依据与边界见 [REALISM_PLAN.md](REALISM_PLAN.md)，本轮整体集成和发布须以 [VERIFICATION.md](VERIFICATION.md) / [DEPLOYMENT.md](DEPLOYMENT.md) 的实际结果确认。

四肢 IK 复用 MIT Three.js CCDIKSolver，用共享 25 关节定义适配现有骨架。手目标为腕/Hand，脚目标为踝/Foot；目标和可选 pole 是世界坐标。人体弯曲方向初始化解除直链奇异，逐轮投影到现有关节复合包络，保持骨长、Root 与非链关节。目标不可达返回米制残差，不拉长骨骼；可选世界末端朝向也受腕/踝限制。IK 编辑先形成完整 Pose 草稿，仍须明确写 K；单轨写入保留其余草稿，完整姿态 K 才一次提交全部变化。

`KeyframeSequence.footLocks` 为可选元数据，每条包含 `schema: foot-lock-1`、独立 ID、左右 Foot、整数 startFrame/endFrame、世界脚踝 target、世界脚部 rotation 与 blendFrames。最多 32 条，同脚闭区间不得重叠；过渡 0–15 帧，区间内部平滑进出，场景首/末端不为边界强制解锁。锚点来自实际 FK，脚踝和脚尖/脚跟中心不能冒充脚底。不可达位置和朝向都报告残差；明确支撑约束必要时只降低 Root Y，Root X/Z 不自动改动。

新增/移除脚锁属于明确动画提交，进入同一历史和本机场景/完整备份，不能由跳帧或播放自动创建。写K、删除和键转移深拷贝保留脚锁；删除K不表示删除锁。带锁序列从不可变基底与稀疏轨求值，再在30 Hz接触样本解算；明确作者K通道优先，附近三帧平滑减弱自动修正，保留原显式时刻、作者数值和精确末样本，不逐帧增加轨道键。4096键/6001样本上限继续有效。旧序列没有脚锁时行为保持；移除全部锁和全部K后恢复原基底。

新增与实际编辑后的序列可选保存 `authorKeyPriority: author-key-priority-1`。新求值始终采用作者优先；旧无标记的已保存权威Take不在打开时重烘焙。备份对整份动作严格匹配新求值，只有无标记的旧脚锁序列可以整份匹配确定性旧求值；不能逐帧混合两种算法，新标记与未知版本不走旧算法兜底。真实键/锁/转移修改升级标记，空删除与空转移不迁移或新增历史。

标准 `neutral-adult-v2` 参数默认内置：约 1.85 米/70 千克，16 段对称质量分布、局部质心、姿态相关惯量、重力 9.81 m/s²、地面摩擦/恢复系数和有限辅助驱动。用户无需输入这些数值。诊断只读显示脚底接触、穿地、身体代理穿插和准静态重心支撑；动态/腾空状态不以站姿投影规则硬拒绝。

Rapier 动力预览是按需运行的独立候选，固定 1/120 秒步长，输出 30 Hz、原输入时刻和精确末样本。当前动态整体包络应用重力、地面接触、摩擦及有限水平驱动力/扶正力矩，保留作者肢体姿态；未实现每段独立刚体、关节 motor 或完整主动平衡。模拟先预览/取消，明确采用后才固化为新权威 Take，原稿保留在共享历史；播放或跳帧不运行模拟、不偷偷修复。

本轮 Workers AI 只做受限模板编排候选；用户禁止真实 AI 推理测试，所有验证仅 mock/fixture。AI、物理与模板候选同样受作品版本和取消保护，不上传原音乐或自动云保存，也不表示真实舞蹈/教师认可。

选中关节仅做选择，不自动进入编辑或改变动画。首次使用和新场景默认手动模式；旧场景恢复保存的模式。舞台工具栏提供选择、旋转、整体移动，选中手脚后出现 IK；v14取消「数值微调」和侧栏参数组，使用舞台直接操作。手机点击编辑工具保留舞台位置。定位和所有 K 操作均在舞台下方时间轴，右侧不再保留精细关节面板。

视口操作环在未镜像、暂停的编辑模式下围绕选中关节，以 local 空间旋转；整体移动将 TransformControls 绑定 Root，以 world 空间 XYZ 箭头移动整个角色，不平移单个关节或改变骨长。拖动操作柄暂停相机操作，空白处仍可导航相机。Root 拖动与数值使用同样范围：X/Z ±5 米、Y 0–3 米。

显式点击旋转或整体移动工具可以进入编辑：播放中须读取实际音频时间后暂停并对齐当前帧；镜像须返回未镜像姿态；候选/教学观看须明确返回原稿。候选动作不能被写为草稿或无提示采用。尚无动作时禁用工具并给出生成初稿提示；末端节点禁用旋转并说明只读，仍允许整体移动。镜像仅用于观察，不从镜像空间写入动作。

工具/场景切换或取消拖动时须清理 capture、活动指针与选点起点，恢复相机和下一次选择/操作柄拖动。操作柄被第二触点打断时，隔离该组触点直到全部抬起，不让第二触点驱动原生操作柄；随后正常双指相机手势仍可用。

## 相机全身取景与关节聚焦 · version 9 已交付

新增「全身取景」和「聚焦关节」两个明确动作。用户将 Root 移到画面外后可以重新框入人物；选中关节后可以近距离观察和摆姿。取景基于此刻实际显示的骨架，而非固定站姿或场景原点：包含当前草稿、镜像、候选和教学显示的姿态。6 个只读末端虽然不能旋转，仍可聚焦观察。没有动作时不能取景，没有选中关节时不能聚焦，禁用原因须明确。

相机沿当前观察方向重新定位，保留侧面、俯视等观察角度。全身取景计算可见骨架的包围范围，并按当前舞台宽高比、透视和相机范围留出边缘，桌面和手机均应完整入镜；关节聚焦以选中节点的可见世界位置为中心，使用适合局部观察的距离。镜像仅在可见空间参与取景计算，不反写 Root 或关节数据。

取景只修改相机视图，不改变选中关节、当前帧、播放状态、实际音频、草稿、候选/教学状态、权威动作、手 K 轨、revision、历史或教师确认。它不触发草稿写入/放弃弹窗，也不将候选变为原稿。相机变化可以标记本机场景视图未保存，沿用 `viewer.camera` 事务保存/重开，不为取景扩展 Scene 协议或保存命令。

每次取景请求按当时的可见姿态执行一次；后续跳帧、姿态更新、拖动相机或窗口变化不重放旧请求，也不自动跟随人物。应用场景时清空待处理请求并恢复该场景相机。取景前须安全取消活动旋转/Root 操作柄拖动，保留最新已形成的草稿，清理指针及相机控制权；被打断的多触点手势继续隔离到全部抬起，避免后续事件把姿态或相机推回旧位置。

### 关键帧时刻移动与复制

时间线筛选范围决定操作范围：选中关节只处理该旋转轨，Root 只处理位置轨，全部轨处理源帧实际存在的显式键。用户输入合法 30 fps 整数目标帧，再点击复制或移动。复制保留源键，移动移除被转移的源键；未在源帧写键的轨、目标仅有的其他轨和 6 个只读末端保持原样。不从插值姿态、未写草稿或隐式基底端点生成源键。

目标已存在源键对应的同轨 K 时，先列出冲突并要求取消或明确替换；其他目标轨不删除。弹窗前固定操作种类、范围、源/目标帧、场景与 CountMap，草稿处理后复核来源。用户选择先写完整姿态时，这是独立的明确 K，转移使用写入后的源轨；随后取消转移不会撤销该 K。冲突确认另绑定序列 ID 与 revision，旧确认不能覆盖后续编辑。

源帧等于目标帧、范围内没有源键，或确认复制后目标显式数据逐分量完全一致时不新增动画版本/revision/历史。正式转移先校验 4096 轨键及 6001 采样上限，再从原不可变基底烘焙，成功后形成一个转移历史条目并跳到目标帧；错误或超限不允许部分改写。撤销/重做恢复对应序列，场景保存保留结果。

移动/复制只调整固定时长内的键时刻，不伸缩音乐或 CountMap。旋转 SLERP、Root 线性插值继续作用于相邻锚区间，影响可以跨八拍，不宣称仅改变源和目标帧。播放、镜像、候选/教学只读观看及末端旋转范围不能执行转移；无键、同帧和非法目标须准确禁用。

### 场景备份与键盘操作

「下载完整场景包」包含原音频与正式场景数据，先处理草稿；「下载项目备份」沿用不含音乐的旧 JSON。「场景 → 导入场景备份」校验后创建新 ID，清空教师确认，保留精确 Take/基底/轨道/历史/相机及有效旧稀疏采样，不由 plan 再生成。JSON 须重新关联原音乐；完整包音频验证 hash，并实际解码核对时长/选段。新场景事务完成后才应用，失败不覆盖当前作品。具体格式与累计资源规则见 [SCENE_BACKUPS.md](SCENE_BACKUPS.md)。

已有保存场景若缺少原音乐，保持其原动作和数拍，清空播放器源，禁用播放、保存和完整包下载；项目 JSON 仍可下载。明确的「恢复原音乐」绑定当前场景/CountMap，实际解码核对时长和全部历史选段覆盖；处理草稿后捕获最新已写 K 的正式项目与当前视图，保存为新 ID，旧场景及其缺失音乐状态保持原样。它不调用音乐重新确认、清轨或重烘焙。恢复分支已通过相关本地复核、本轮线上流程及完整源码 CI。

所有模态操作只允许最上层对话框接收焦点；Tab/Shift+Tab 环绕，Escape 在非忙碌状态取消最上层，并恢复仍可用的触发者或同功能区域焦点。多层草稿/场景确认遵守视觉层级；自动聚焦的改名输入保持不变。对话框打开时暂停舞台编辑，取消不写 K、不确认删除或采用；没有模态时不拦截普通键盘操作。

## 草稿、提交与历史

舞台操作柄先改变当前帧的完整 Pose 草稿，舞台即时预览。切换同一帧的选中关节或选择/旋转/整体移动工具可继续摆姿态，不写 K、不增加历史。选择工具隐藏操作柄，但保留手动模式和当前草稿；实际离开手动编辑模式仍须处理草稿。镜像观看期间草稿只读，再次显式点击编辑工具可返回未镜像姿态继续编辑同帧草稿。草稿不能被当成已写入的关键帧、权威动画或已保存场景。

用户显式写入当前关节、Root 位移或完整姿态。同轨同帧写入为更新，不产生重复键；完整姿态一次写入 19 个旋转和 Root，成为一个撤销条目。关节和 Root 分别显示当前帧是否有显式 K，不能以插值姿态或尚未写入的草稿冒充键。v7 将 core 的单轨删除接入 UI：分别删除当前关节旋转键、Root 位移键，保留「删除当前帧关键帧」并明确说明移除本帧全部轨的全轨操作；单轨删除不得删除同帧其他轨。

删除请求先固定其种类、关节和帧，再处理未写草稿；确认后继续执行原目标，不能因弹窗期间的选择或时间变化改删其他键。目标无显式键时不提交、不重烘焙、不增加 revision 或撤销条目。每次真实的正式动作修改生成新动画 ID、增加作品 revision，并清空旧版本的预览确认；旧候选不可覆盖新动作。

跳帧、播放、切换场景/编辑模式、撤销、改音乐或生成模板前，未写入草稿须明确选择写入后继续、放弃或取消。场景保存也经过这一处理；存储事务失败不显示保存成功，当前修改仍可继续编辑。

沿用每场景 12 步历史，不另建与编排分离的撤销栈。相机、镜像、关节选择不修改权威动画，也不触发重新烘焙。

## 场景内姿态复用 · version 8 已交付

复制当前原稿编辑姿态，包括尚未写 K 的草稿；显示来源帧和原稿/草稿状态。剪贴板保存独立深拷贝，后续摆姿或动画提交不能改变已复制的内容。复制本身不改变权威 take、revision、历史或场景保存状态。播放、镜像、候选和教学观看期间禁用复制/粘贴，不能从候选姿态隐式生成或采用动作。

「粘贴关节姿态」复制 19 个可编辑关节的父相对旋转，保留目标帧 Root 位置及 6 个只读末端旋转；第二个选项同时复制 Root，按现有 X/Z ±5 米、Y 0–3 米范围限制。两种粘贴都先成为目标帧的完整 Pose 草稿，舞台即时预览，不直接写 K、增加版本或历史。显式写入当前关节或 Root 后，其他尚未写入的变化继续作为草稿；完整姿态写 K 才一次提交全部可编辑轨。

目标帧已有草稿时，粘贴复用写入后继续、放弃后继续、取消的确认。弹窗前固定粘贴种类、复制内容和目标帧；后续剪贴板、选择或时间变化不能改变待执行请求。取消保留原草稿，处理完草稿才将捕获内容应用到原目标帧。

剪贴板只属于当前场景的页面内存，不读写系统剪贴板、不调用 API、不随 Scene、JSON 备份或历史保存，也不扩展数据协议。应用新建/打开/复制等场景、刷新页面或确认音乐/CountMap 变更时清空，防止跨场景套用。普通写/删 K、撤销/重做与同场景模板操作可保留复制内容。

## 轨道查看与跳 K

时间轴的上一/下一 K 在当前筛选范围的显式键时刻中查找严格早于/晚于当前帧的相邻键；跨所有轨查找时先选择「全部轨道」。不会反复跳到当前键，也不会把未写入的 0 帧或结束基底锚作为 K。没有对应方向的键时禁用按钮，逐帧和秒输入继续可用。

时间线提供全部、当前关节和 Root 三种查看范围。标记、列表、键时刻数量及时间线跳 K 均取自当前范围的显式键；全部轨同帧的键合并为一个时刻，当前关节和 Root 只显示各自轨。未选关节时说明需要先选择，6 个只读末端说明没有可编辑旋转轨，空轨明确显示没有显式 K；不能回退显示其他轨而让用户误判。

筛选是临时观看状态，不改变 take、revision、历史或保存契约，不加入 `viewer` 持久化。筛选本身不处理或提交草稿；通过上一/下一 K、时间线标记或列表跳帧仍复用现有未写草稿的写入、放弃、取消确认，不直接绕过保护。

## 动画数据与插值

每个 Snapshot 可选保存 `manual: KeyframeSequence`，包含 `schema: manual-keyframes-1`、固定 `fps: 30`、不可变 `baseTake`、按关节的稀疏旋转轨和独立 Root 位置轨；v12 另可选 `footLocks`。键记录整数 frame；输出仍为 `BakedTake`，播放、观察和 JSON 备份消费同一权威产物。

有显式键的轨以基底在 0 和精确结束时刻的姿态作为隐式端点，用户写入端点时替代该端点。相邻旋转键最短路径 SLERP，相邻 Root 键线性插值；这会影响相邻键之间的整段该轨，不宣称只改当前帧或选中八拍。未编辑轨继续使用原基底样本；明确脚锁在此基础上解算其支撑链及必要的 Root Y。删除最后一个显式键后，该轨回到基底；没有脚锁时全部键删除保留原始 poses/times，只生成新的动画版本。

烘焙保留基底的显式时间数组、八拍边界与精确末样本，同时加入显式键时刻。不能由 plan 再次生成 base，也不能把已编辑输出不断叠成旧轨的新基底。有限数、合法节点、整数帧、非零四元数、资源边界必须在编辑入口校验；整个序列最多 4096 个轨键，输入与输出都最多 6001 个显式样本，超限明确拒绝。

“从站姿开始”在同一音乐/CountMap/场景下建立中立原始姿态，方便用户构建自己的序列；清空已有手 K 的操作可撤销。模板重新生成清空手 K；采用八拍替换直接消费候选的权威 take，将当前可见动画固化为下一次编辑的基底、清空旧可编辑轨，须明确提示且可撤销。范围外不变仍按替换的权威动画检查，不能保留旧轨再次覆盖新基底。

## 保存与兼容

编辑序列、基底、权威 take 与历史作为 SceneDocument.project 一起由 IndexedDB 事务保存，原音频仍单独包含在同场景。viewer 可选保存 editorMode 和 transformTool（select/rotate/translate；v12 增加 ik）；旧 `choreo-scene-1` 没有工具字段时，手动模式默认旋转、编排模式默认选择。旧 Scene 无 editorMode、Snapshot 无 manual 或 sequence 无 footLocks 时按已有动作恢复，不重烘焙旧 plan，不替换原音频。恢复工具是视图恢复，不是动画提交。

音乐或 CountMap 发生改变时旧手 K 不自动套到新时长。JSON 备份包含正式编辑序列与权威结果，未提交草稿不假装保存成功；v9 以前只有 JSON 下载，v10 已上线导入及含原音乐的完整包。旧 JSON 仍须另行保留并关联原音乐，不能用音乐设置重建动画代替恢复。

编辑、播放、烘焙、轨道筛选和保存均在浏览器本机运行，无业务 API 调用、自动云保存或 D1 写入。v7 未修改 core、API、基础设施或已有数据契约；姿态复制当时不在其范围内，由 v8 单独实现。v8 仍不增加 IK、自由音乐时间线或服务写入。验收优先本地数学/交互测试；正式部署只做一次必要的公网流程验证，继续保留已配置的原生 API 限频。

v9 的相机取景也不增加自动跟随、相机动画、动作变换、IK、音乐时长编辑或云服务；已有编辑和持久化规则继续适用。
