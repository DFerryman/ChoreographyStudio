# 人物碰撞代理与可复用离线生成

## 2026-10-10 · 自由摆姿与派生碰撞预览（已发布，公网及准确CI通过）

摆姿编辑取消身体／地面碰撞截停，继续显示并记录作者姿态；原有关节指导、Root 数值边界和显式辅助数据规则分别保留。播放、Timeline 正反拖动及直接定位使用 `sampleCollisionPreview`：先在原 Take 的精确秒值采样，再对该姿态进行确定性的接触投影，不以先前显示姿态推进隐含模拟。

预览复用当前 17 个凸包及 Rapier 0.21.0 的接触点／法线查询。身体接触最多进行 4 轮有限局部旋转修正，只接受使代理穿透代价下降的结果；之后根据身体代理与已标定脚底角点的最大地面深度，作所需的最小 Root Y 抬升，保持 Root XZ。无法消除的接触继续作为残差显示，不暗改作者数据。它不是重力、速度、主动平衡或高精度蒙皮求解，也不保证相邻查询之间连续零穿透或无抖动。

预览结果只存于内存：按 Take 对象与模型配置对象分别缓存，每组最多 256 个精确查询时刻，淘汰旧结果；不按动画 ID、访问方向或播放速度推进状态。作者编辑、撤销或场景替换使用各自的 Take；预览不会写回 Take、manual、K、历史、原时刻或备份。重新点选部位或工具进入编辑时，先恢复作者姿态，再捕获原生操作柄基准。碰撞 backend 的加载／失败与人物作者编辑就绪分开，失败应显示真实反馈并允许继续摆姿。

## 为什么当前人物选凸包

胶囊适合接近圆柱的骨段，但统一圆形截面会扩大宽扁的胸、髋、腿和手。当前人物完整大腿皮肤的圆形包络半径约 126.7 mm，会把实际分开的双腿判成重叠。单个盒也会把弯曲边界外的角落算成身体。

因此当前配置从每个解剖区域的全部皮肤点生成凸包。17 个区域是髋、腹、胸、颈、头，以及左右上臂、前臂、手、大腿、小腿、脚。手指仍属于手部区域，未为消除默认告警而删除。凸包保留截面宽度、厚度和锥度差异，避免圆胶囊与宽盒的明显误报。

模型、来源许可和显示标定保持原样：官方 CC0 Quaternius，65 个原生显示骨与四个原始权重槽，25 个编辑关节不变。原始 GLB、rig JSON 和冻结的模型 README 均未修改。

## 生成与核对

通用算法在 `infra/avatar_collision_fit.py`；当前模型的读取、权重区域映射和现有脚底接触参数在 `infra/quaternius_collision_fit.py`。模型名称、65 骨、8,483 点等假设只在适配器中，通用算法不限制为这一人物、顶点数量或左右对称形态。

需要 Python 3.11+、NumPy 2.3.5、SciPy 1.17.0；当前实际环境是 Python 3.12.14。固定依赖见 `infra/requirements-avatar-fit.txt`，BSD 许可说明见 [AVATAR_FIT_DEPENDENCIES.md](AVATAR_FIT_DEPENDENCIES.md)。这些 Python 库只用于离线生成，不进入浏览器应用。

```sh
npm run avatar:fit
npm run avatar:fit -- --check
npm run avatar:fit:test
```

第一条命令重新生成 `packages/core/src/avatarCapsules.generated.ts` 和 `infra/quaternius-collision-fit-report.json`。`--check` 只读核对生成内容与当前源模型、参数和固定依赖；不写文件。脚本不发网络请求，也不修改模型、姿势、作者键、质量、惯量或接触阈值。

当前适配器直接读取 GLB 的位置、原始浮点权重和关节索引，按已经审查的 `runtimeCalibration` 计算中性显示皮肤。它不重新归一化权重。每个顶点按解剖区域的权重总和选择最大区域；当前凸包包含分配到区域的全部点，包括关节混合点和手指。

为避免不同 CPU 的 LBS／BLAS 最后几位浮点尾数影响凸包或几何 SHA，算法 v2 先将输入世界点、关节位置和四元数组件规范为 9 位小数，四元数再按固定标量运算顺序归一化并固定符号；转换到局部空间的点也在 Qhull 前量化为 9 位。几何 SHA 使用固定 9 位十进制表示，不直接哈希裸 LBS 双精度尾数。合成用例实际加入最后 1 ULP 的位置／旋转扰动，验证局部凸包与几何 SHA 保持一致。

通用算法接收世界空间中性皮肤点、区域标签、规范关节中性帧与区域配置。它先计算 `p_local = Rᵀ × (p_world − joint_position)`，再在相应关节局部空间拟合。中性帧可有平移和旋转，未假设所有输入帧旋转为零。SciPy `ConvexHull` 输出局部凸包顶点；面索引逐面校正为朝外，并稳定排序。额外包围盒覆盖凸包，供运行时快速排除。

胶囊、盒和凸包的尺寸都由输入点重新计算。可选 `parts` 配置支持确定性的分段，`orientation` 支持骨架轴或 PCA；当前凸包不分块、不裁去低权重点。碰撞配置与 `STANDARD_HUMAN_PROFILE` 的质量、重心、惯量保持分离。

| 配置版本 | `quaternius-mixed-collision-1` / 1 |
| 算法版本 | `local-convex-and-primitive-fit-2` |
| 规范骨架 | `neutral-rig-2` |
| 源中性显示顶点 | 8,483 |
| 凸包数量 | 17 |

| 生成 TypeScript 大小 | 约 112 KiB |

源 GLB SHA-256 为 `6570b23a63a0a5b87ad3fa5f8d7a24536c8e7fc3ceb03d28893cb48966cc6527`；rig JSON 为 `882e122c2d497ea7c23ce073eefe3ddc3d09b6992f814a586b5b9ca658b7e68b`。中性点、区域与规范帧的几何 SHA-256 为 `28277b1614a4d61330b28d28992b97d1456eec7951b56590e69ce880feb73f90`。生成配置记录这些校验、配置版本与算法版本，模型替换必须重新生成并匹配新资产。

独立 SciPy 半空间可行性检查使用同一 9 位坐标规范，实际检查了 119 对非邻接源区域。只有左右手与同侧大腿的两个**源区域凸包**重叠；前臂与髋、腹、胸和对侧双腿均不重叠。左前臂到髋、腹、胸的最近采样顶点距离分别是 14.79、19.07、44.12 mm；左右腿为 12.92 mm。这些距离是顶点采样距离，不能代替连续三角面的最小距离。

每侧手有 297 个源点位于同侧大腿的源凸包内部，大腿有 12 个点位于手凸包内部；最大点到凸包最近支撑平面的内部深度约 44.76 / 30.37 mm。这说明当前中性源区域的凸包确有既存交叠，不能宣称中性姿态零碰撞，也不能把这个数值称为 Rapier 的最小分离位移。手指间隙等凹形会被凸包填满，因此这一结果仍不是三角面实际穿插的完整证明。运行时应报告既存接触并允许离开，保留源动作，不删除手指或排除手腿碰撞来隐藏问题。

完整区域数据、覆盖数和独立源凸包检查均保存在 `infra/quaternius-collision-fit-report.json`。相同生成命令和 `--check` 已实际通过；通用算法 6 个 Python 用例和源资产 2 个 Vitest 用例已实际通过。后者从冻结 GLB 独立计算全部 8,483 个中性蒙皮点，再检查相应凸包的朝外半空间，门槛为 10 nm。

脚底继续使用当前版本的 82 mm 深度和原四角接触定义，地面穿透门槛仍是 3 mm。中性显示脚部源顶点最低点相对脚关节是约 83.573 mm；Root 为 1.05 m 时该点实际高于地面约 6.427 mm。凸包的更宽角点不替换既有脚底接触协议。未来模型必须提供自己的 `footGround` 标定或使用新配置对应的真实脚部形状，不能静默继承旧人物脚底尺寸。

## 更换人物时的复用流程

1. 将新模型的显示皮肤与编辑骨架对齐到规范关节，输出该模型的**已标定中性世界点**、逐点解剖区域标签和关节世界帧。保留新模型的原始文件与许可信息；当前 Quaternius 适配器不负责猜测其他模型的原生骨名。
2. 建立 `avatar-neutral-collision-input-1` JSON。每个区域给出 `id`、绑定关节 `frame`、`attachmentJoints`、`family` 和 `shape`（`convex`、`box` 或 `capsule`）；配置可指定分段与拟合点置信度。填入新模型 `sourceGlbSha256` / `sourceRigSha256`、自己的配置 `profileId` / `version` 和脚底标定。
3. 使用通用输入重新生成、检查覆盖报告与默认姿态，再按新模型的常用动作验收和发布。新旧资产必须绑定各自配置；骨架长度、Root、作者数据不会因拟合而改写。当前没有新增用户模型上传界面。

```sh
npm run avatar:fit -- --input work/new-avatar-neutral.json \
  --output work/new-avatar-profile.ts --report work/new-avatar-fit-report.json
npm run avatar:fit -- --input work/new-avatar-neutral.json \
  --output work/new-avatar-profile.ts --report work/new-avatar-fit-report.json --check
```

输入格式的最小结构如下；`positions`、`regionAssignments` 和 `groupConfidence`（可省略，默认为 1）长度一致。实际人体应提供完整区域和规范关节帧，这里只展示字段。

```json
{
  "schema": "avatar-neutral-collision-input-1",
  "profileId": "new-avatar-collision-1",
  "version": 1,
  "canonicalRig": "neutral-rig-2",
  "positions": [[0,0,0],[0.1,0,0],[0,0.2,0],[0,0,0.1]],
  "regionAssignments": ["body","body","body","body"],
  "frames": {"Hips":{"position":[0,0,0],"rotation":[0,0,0,1]}},
  "regions": [{"id":"body","frame":"Hips","attachmentJoints":["Hips"],"family":"trunk","shape":"convex"}]
}
```

通用验证实际使用了 9、23、29、37、41 等不同点数，缩放、非对称几何、带平移与旋转的规范帧及自定义 CLI 路径；验证新输入会产生新尺寸、新局部顶点与新几何校验，并检查面方向、包围盒覆盖和拒绝非有限输入。

历史手势保护实现（由上方最新编辑／预览策略取代）：运行时共享一次 Rapier 初始化和缓存凸形状，不建立重力 World。新的手势沿最短旋转／线性 Root 路径检查，每个旋转样本最多 2°、混合 Root 样本最多 1 cm，遇新增或加深的接触后细分边界；纯 Root 位移使用不变的自身接触与单调地面深度。已有接触可向外调整，未改作者值保持。接触预算采用 Rapier 的数值接触深度，不是所有几何下精确的最小分离位移；只有数学上包含全部八角、确实等同盒子的凸体使用解析盒检测，普通人体凸包仍走窄相查询。

100% 中性顶点覆盖不保证所有姿态的连续蒙皮都处于代理内。凸包会填充凹处，刚性骨段代理无法精确重现关节混合、指缝和面部细节；离散路径检查不能证明采样之间完全无碰撞。动态动作、脚锁、限位与作者优先各有独立验收。此配置提供更贴近当前人物的碰撞查询，不代表完整软组织碰撞或全身动力学。
