# 真人动作先验

本轮用户授权以真实动作先验改善 AI 生成：文本模型负责理解描述和选择、组合已有动作；人体求解与采用门槛由程序处理。这些数据是产品内部的动作参考，不增加预设场景入口，也不恢复六个程序动作模板。

## 数据与构建

`apps/web/public/motion-priors/*.motion` 是动作专用二进制：16 字节标识、长度受限的来源 JSON，再跟每帧的精确 Float64 秒值、Root 与 25 个局部 XYZW 四元数的 Float32 数据。采样为 30 Hz 加精确结束点，降低原 60/120 Hz 的存储与下载量；不能声称原捕捉采样无损。加载只归一化 Float32 量化后的四元数，不修改原场景或播放中的作者值。

目录包含两个完整参考与十二个带来源区间的子片段：街舞 `a..e` 对应 0–8、8–16、16–24、24–32、32–37.5 秒；Salsa `a..g` 对应 0–8 到 40–48 秒的连续八秒窗口及 48–56.25 秒。标签区分站立步法、转向、低位与倒置；Salsa 转向幅度来自捕捉 Hips 朝向的展开角度范围，不是指定歌曲的编舞注释。动作标签和接触提示仍是描述或假设，不能替代实际轨迹验证，也不能证明参考库覆盖其他舞种或任意指定动作。

此前重定向器把左右肘弯曲平面放在 ±30° 的 carrying frame 中。内部先验将这个固定 Y 旋转转移到 UpperArm 的轴向旋转，并在 ForeArm 左乘其逆旋转。由于肘位置的局部偏移沿 −Y，肘、腕、手及其后代的世界位置、前臂与手的世界旋转保持不变；上臂轴向朝向明确改变，肘弯曲回到统一 −X 功能轴。原掌部映射还把前臂旋前、旋后分配到了 Hand：第二步将其纵向 Y 旋转转移到 ForeArm 的 ±110° 工程包络，无法全部转移时在腕部保留残量。第二步改变前臂轴向朝向，仍精确保留腕部、手及手指末端的世界变换；两条来源在量化前各步骤的组合世界四元数分量误差上限均为 `4.440892098500626e-16`。这些是功能轴重定向，不是扩大人体包络或认证碰撞无误。

踝部纵向 Y 旋转还在原有小腿 ±25° 预算内连续转移到胫骨轴向，目标踝包络保持 ±30°；成对逆旋转精确保留 Foot、Toe、Heel 的世界位置与旋转，量化前组合旋转误差同样不超过 `4.440892098500626e-16`。这改变小腿皮肤的轴向朝向，工程映射仍受膝屈曲角度影响，不是临床活动范围证明。完整 Salsa 与最初八秒站立街舞在这些轴向预算内；完整街舞的复杂低位片段仍有 27 个 LeftFoot 帧无法把合计旋转全部分配到两者的 55° 预算，残量保留给采用门槛，不扩大约束，也不声称十四个片段全部可行。

离线构建命令如下，输入目录只能是两个经 SHA 校验的公开场景包。脚本不会下载、执行场景内容或复制音频：

```sh
python infra/build_motion_priors.py --source-dir /path/to/public-source-packs
```

目录元数据与每个产物的 SHA 在 `packages/core/src/motionPriors.ts` 固定。浏览器仅在明确生成后加载模型实际选中的同源动作文件，单文件上限 1 MiB，完整 SHA 校验后解码并缓存不可变数据；没有整个场景下载、用户音频上传、后台推理或自动重试。

每段还带有实际二进制存储的起终点 Root XZ、Y 与 Hips 水平朝向标签，朝向在倒置或近竖直时标记 unknown。`wholeClip.*` 事实只适用于整段选取，不能推出任意子区间的端点；模型应利用冻结的用户端点和可信来源事实规划可达的区间连接。

构建脚本的 JSON 回执含六条 `endpointFacts`：从已量化、实际写入的首尾帧计算 Root 精确数值，朝向为六位小数角度或 unknown；这些标签保持每条最多 80 字。目录把回执事实连同动作描述发送给模型，单段标签总数最多 16，单元测试逐条核对十四个文件的 Root 标签和实际解码值。回执只读事实不会增加动作文件或请求中的用户数据。

## 组合与质量边界

模型返回选用片段、真实源区间、目标时间、朝向、额外水平移动、衔接长度和接触假设。程序重定时、绕 Y 转向、按 Root XZ 对齐，并在新段内部根据前一段只读末姿态与速度做有限延续、平滑过渡，不读取未选源区间的后续姿态；完整生成的末段逐渐减速，区间修改的两头在区间内部过渡到只读原姿态和速度。产物是密集的独立候选曲线，原 Take、外部采样、两端数值和作者文件由既有轨道层保护。

新生成还根据固定 Quaternius 碰撞几何，把供体的手路径适配到当前人物的体宽、手掌尺寸和固定臂长。程序在胸部坐标中基于实测凸代理的包围盒，连续计算身体表面外的腕部、肘部与前臂中点目标，使用源姿态和上一帧修正作为初值，以固定次数的局部阻尼最小二乘解上臂三个自由度和肘功能轴；外层有限迭代使用拟合后的实际掌部朝向。头部另用实际头部顶点的包围球与掌部实际最大半径构造保守目标域，避免轨迹平滑切过头部边角。最终碰撞检查仍使用原凸体，未替换或扩大身体代理。保守目标会改动部分原本无实际接触的手势，因此不宣称改动最小。保留局部腕部动作，对既有腕屈伸 −80°..85°、侧向 ±40°、轴向 ±15° 和总摆动 85° 工程包络在新生成时留半度内部余量；不逐帧强行补偿手掌世界旋转。

所有下肢、Spine、Neck、Head 的连续场先完成，再根据当前身体几何完成最后一次手臂拟合，随后对新候选手臂做 75ms 内禀 SO(3) 全轨迹平滑。不会在最终手臂平滑之后重新逐帧 IK。冻结边界以 C2 权重收回修正。原音乐、场景和来源数据均不改动；接地阶段另行处理新候选 Root。

Salsa 另有专门的供体到人物下肢适配 `quaternius-cmu61-stance-1`，在手臂几何计算之前执行。独立实际蒙皮测试显示两种中性姿态原本均无大腿交叉，而源 Salsa 部分姿态存在严格三角形相交；不是忽略代理对就能解决的问题。有限扫描实测选出上腿轴向 Y 保留一半、左右上腿父坐标 Z 各向外 5.5° 的连续映射，保留源膝功能平面、节奏与局部下腿弯曲。先恢复源世界脚底朝向，再在胫骨 ±25° 内分配踝部轴向余量，容量不足时对踝屈伸 −60°..40°、侧向与轴向 ±30°、总摆动 65° 做连续投影，脚的位置和脚底朝向成为显式软目标。这个经测量的校准只用于 CMU61 站立 Salsa；不擅自扩展到街舞倒置和地板动作。

为避免轴向分配在胫骨容量边缘产生快变，`shin-axial-trajectory-1` 还对新候选小腿纵向 Y 场做 75ms 对称角度平滑，保留膝屈伸平面与节奏，并将逆旋转配给 Foot。只要踝包络允许，脚踝与世界脚底变换保持精确；容量不足时脚底仍为公开软目标，不扩大角度包络。这个步骤不改源资产和原场景。

独立真实插值检查还发现原下腿屈伸、上腿、躯干与头颈映射的高频变化超过固定加速度门槛。`knee-flex-trajectory-1` 对新候选膝功能 X 做 50ms 连续平滑，保留源侧向分量，并用脚局部补偿保持世界脚底朝向作为软目标；脚踝位置会有额外改动。Salsa 上腿、Spine、Neck 与 Head 另做 50ms 内禀 SO(3) 调节，分别记录 `upperleg-so3-trajectory-1`、`spine-so3-trajectory-1`、`neck-so3-trajectory-1` 与 `head-so3-trajectory-1`。这些调节只影响新生成候选，原场景、原播放和区间冻结两头保持不变。

完整生成结束时直接暂停任意捕捉帧可能不能静态站稳。因此 `full-hold-settle-1` 仅在新完整候选最后 1.5 秒以 C2 权重构造稳定收势：保留每帧 Root XZ 和最终水平朝向，逐渐回到 RootY1.055、手臂张开15°的校准站姿，末端归零运动速度。区间修改不执行此阶段，原场景和完整生成最初冻结锚点不变。收势不是无来源动作请求的替代结果，UI 与 `endingAdaptation` 明确披露时长，后续仍需实际插值全轨迹校验。

包含该收势的当前 Salsa32 秒组合诊断观察到：脚踝最大35.443cm、RMS10.078cm，膝最大35.226cm，手最大100.041cm、RMS21.114cm；脚底相对原捕捉方向最大约81.87°。最大值也包括原捕捉正处于运动中途而新结尾回到稳定站立的代价，不应解释成常规小幅修补。每次候选都会重新计算自身数值。来源保留这些总适配值，后续脚底平滑的单独小角度不能覆盖或隐藏大幅收势变化。这是明确动作改编而非原样复现。

2026-10-13 早期完整16秒夹具曾在2539个自适应采样下全部违规为零，最高采样加速度240.06rad/s²。独立微步长检查随后测出靠近结点的 Head 实际单侧加速度259.39rad/s²，超过固定250门槛：旧采样结果不足以证明通过。门禁因此增加每个曲线段的单侧小步长 SO(3) 加速度探测，阈值保持不变。

在补齐真实脚部地面覆盖后的当前 V7 管线中，完整16秒与默认时长32秒 Salsa 均以 `correct:false` 通过加强后的独立门禁：限位、自碰撞、地面、接触、平衡、净支撑力、摩擦、速度与加速度违规计数全部为零。16秒最高关节加速度199.71rad/s²，独立更小步长复核最高199.16rad/s²，Root接地最大约40.13mm，最低法向支撑力81.13N；32秒最高加速度236.65rad/s²、速度12.10rad/s，Root最大约40.13mm，最低法向力37.60N。32秒摩擦锥超量峰值约1.43N，低于固定52.5N数值容差，因此违规计数为零，不称数学误差精确为零。完整32秒还覆盖5261个自适应采样及1920个单侧加速度探测模板。这些数值来自当前固定管线和指定来源窗口；其他区间、时长、风格及拼接仍需逐候选独立验证。浏览器采用与持久化回归、公网推理及部署由主流程另行验收，不能把数值夹具通过写成已发布。

真实 GLB 蒙皮复核曾在早期 V4 候选中发现地面漏检：3.425秒实际脚趾低于地面22.32mm。独立定位证明最深顶点为纯脚趾骨权重、刚性脚坐标，真实脚凸包与蒙皮最低高度一致；脚尖比替代脚底盒长44.52mm。新生成的地面、支撑与曲线接地已经统一包含原有真实 Foot 凸包及保守旧脚底盒，恢复被遗漏的几何，没有缩小代理、扩大角度/碰撞阈值或修改源数据。旧播放器和编辑器的既有脚底契约保持兼容。V7 复核的11个实际网格姿态无自交，脚底最低顶点在固定−3mm门槛内；这仍是选定姿态的独立实物几何复核，不是所有可能动作的网格碰撞认证。

另一个真实区间正例使用完整 `cmu-61-08-c`（源16–24秒），朝向−35°，额外Root平移补偿保持在±2m范围内，把新八秒舞蹈接入4–12秒的运动原场景。加强门禁全部违规为零，最高加速度201.04rad/s²、速度11.59rad/s，Root最大40.03mm，最低法向力70.13N；两端、相邻冻结采样带和外部值精确不变。这个朝向使有效衔接权重处避开最短四元数插值的π分支切换。其他合法源窗口和朝向仍可能因根部六厘米预算、首尾快速转身或该一般 SO(3) 衔接分支问题被拒绝：程序不会放宽预算或显示未通过的扭曲结果。一般连续旋转衔接的进一步处理仍属待改进项，不能把一个相容正例推广成任意朝向都可顺滑拼接。

两个原始公开参考包的时间零有效姿态与新功能轴包络并不完全一致；当前完整生成保留最初冻结锚点，会在调用模型前拒绝这些不合法原锚点。新建校准场景的起姿通过范围、自碰撞和真实脚部地面检查。只读容量复核显示两条真实音乐场景加入16/32秒密集候选和十二个共享历史后仍在32MiB完整备份上限内，源项目、音频与文件未变；容量不是上述原锚点限制的原因。

人物比例适配可能明显改变手势位置，所以候选和持久化来源记录包含适配版本、实际手部位移最大值与 RMS。当前32秒的拟合腕部对目标误差约0.163m最大、0.025m RMS，反映目标并不一定能由固定臂长精确达到。这是保真度代价，不可宣称和原捕捉等同。最终自碰撞、接触、限位、支撑力与密集真实插值质量由独立采用门槛决定；工程代理和采样通过仍不是临床运动范围或完整关节力矩模拟的认证。

浏览器组合过程每 16 帧主动让出任务并检查取消信号，保真度计算也分批执行。当前正确管线的16/32/60秒异步组合在开发机器分别约2.68/5.17/9.86秒，期间定时器能响应164/329/616次；这是组合阶段耗时，不包含加载、接地、求解或模型请求。60秒夹具使用源0–30秒减速两倍，说明1800点预算可分批执行，不作为该完整候选物理通过的证明。派生时间网格排除和精确末点仅相差浮点误差的重复帧，避免极小间隔制造虚假速度与加速度；用户精确冻结时间不被舍入。

真实来源保证了动作先验不是随机全身角度，但不保证任意截取、调速、转向、平移与拼接都能成立。接触、人体限位、自碰撞、地面、运动速度及真实插值曲线仍须通过新求解与验收。低位、倒置和跳跃不能按普通站立自动抬直；不能处理的候选应拒绝。没有对应来源的动作要明确报告覆盖不足，不可把通用 Salsa 结果包装成任意舞种或指定动作。
