# 阶段路线

本仓库以 v2.1 的最小闭环为目标：音乐与数拍确认、单人完整八拍组合、替换一个八拍、教学播放及固定构图 MP4。首轮采用 Web 与成熟 3D 库，先一个动作包、一个 Avatar、一条动作求值路径。当前不接入 LLM。

S0–S3 是本仓库的交付批次，便于逐次部署和查看。它们不替代原规格的 M0–M3，也不代表原验收已通过。

| 批次 | 可查看的成果 | 继续条件 | 对应原任务与里程碑 |
| --- | --- | --- | --- |
| S0：交互预览 | Cloudflare 上的响应式工作台；浏览器读取本地音乐；手动数拍确认；原创 `synthetic-demo` 动作；整段预览、八拍替换、教学播放、撤销及本地保存 | 一次操作闭环可复现；未确认数拍不能生成；替换不改范围外姿态；旧候选不能覆盖新输入；演示边界始终清晰 | R04 工作台骨架，R01 的临时交互边界。合成演示不满足 M0 |
| S1：契约与真实动作 | 导入 original 2.1.0 工程契约；一个有合法来源的小动作包及 Avatar；Python Motion Worker 输出同版 BakedTake；真实整段与局部替换播放 | 原契约验证与生成检查通过；许可记录可核验；一条真实 8 八拍路径及两个非相邻中间槽位可替换；尽早开展教师观察 | R01、R02、R03，R04 接线，R06 早期观察。达成全部素材与契约条件后才可确认 M0；开始推进 M1 |
| S2：服务与运行保护 | 生产 API、身份与权限、PostgreSQL、私有对象存储、不可变版本、任务采用/取消、保存重开和删除 | 版本前置条件、幂等、租户隔离、任务竞态与失败恢复可验证；原稿不损坏；客户端不决定授权或检查通过状态 | R01 生产接线、R04、R06。推进 M1 与 M3 的运行部分，不宣布 M3 完成 |
| S3：教学与有限发布 | 同一 BakedTake 的固定构图 MP4、数拍与提示、镜像/慢放/前导映射、版本绑定教师确认；教师对照与有限试用 | 音画、全身构图、设备和许可验收通过；记录采用、返工、失败与成本；内容与运行保护同时通过 | R05、R06；先补齐 M1 教学视频闭环，再完成 M2 教师验证与 M3 有限发布 |

S0 的公开可访问预览只用于观察交互和开发进度。真实教学用途的开放必须等到内容、许可、教师与运行条件通过。

## 原验收口径保持不变

- **M0｜素材与契约：**真实素材和权利证据、完整数据样例、命令边界与正反例；有真实可编排路径。
- **M1｜最小完整流程：**真实音乐到完整初稿、局部替换和教学视频；可播放、保存、导出，范围外不变，并有早期教师试跳。
- **M2｜教师验证：**留出任务及原流程/同库手选对照；采用、失败、返工、时间和成本有记录。
- **M3｜有限发布：**权限、版本、任务竞态、删除、回滚、设备与导出证据；内容与运行门槛同时通过。

R01 是协议与校验，R02 是真实小包，R03 是编排与烘焙，R04 是最小工作台，R05 是教学输出，R06 是教师试用与运行保护。R01/R02 并行；教师观察从首个可播放的真实组合开始，运行保护从接入服务开始。

## 仓库与部署

采用一个 public 仓库 `DFerryman/ChoreographyStudio`，用共享版本和测试避免首轮拆分仓库带来的契约漂移。

| 路径 | 职责 |
| --- | --- |
| `apps/web` | React/TypeScript 工作台与 3D 播放；消费 BakedTake |
| `packages/core` | 预览契约、数拍与版本规则、统一求值；S1 接入原契约 |
| `services/motion-worker` | Python 动作规划、烘焙与质量检查；后续离线渲染和 FFmpeg 接线 |
| `infra` | Cloudflare 与后续数据、任务、重型服务的部署配置 |

Cloudflare 承载静态 Web 和轻量 API。Python 动作处理、渲染与 FFmpeg 使用独立重型执行环境，不硬塞进普通 Worker。后续依据真实耗时和费用评估 Cloudflare Containers 或外部 worker；保留规格的 PostgreSQL 默认选择，私有对象存储独立于 public 源码仓库。

每次交付先更新状态与限制，再执行相关检查并部署预览。阶段退出使用真实成果和可检查证据，不以测试数量替代动作、教师或发布验收。
