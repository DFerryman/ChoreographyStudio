## 原验收口径保持不变

- **M0｜素材与契约：**真实素材和权利证据、完整数据样例、命令边界与正反例；有真实可编排路径。
- **M1｜最小完整流程：**真实音乐到完整初稿、局部替换和教学视频；可播放、保存、导出，范围外不变，并有早期教师试跳。
- **M2｜教师验证：**留出任务及原流程/同库手选对照；采用、失败、返工、时间和成本有记录。
- **M3｜有限发布：**权限、版本、任务竞态、删除、回滚、设备与导出证据；内容与运行门槛同时通过。

R01 是协议与校验，R02 是真实小包，R03 是编排与烘焙，R04 是最小工作台，R05 是教学输出，R06 是教师试用与运行保护。R01/R02 并行；教师观察从首个可播放的真实组合开始，运行保护从接入服务开始。

## 仓库与部署

采用一个 public 仓库 `DFerryman/ChoreographyStudio`，用共享版本和测试避免首轮拆分仓库带来的契约漂移。

| 路径 | 职责 |
| --- | --- |
| `apps/web` | React/TypeScript 工作台与 3D 播放；消费 BakedTake |
| `packages/core` | 预览契约、数拍与版本规则、统一求值；S1 接入原契约 |
| `services/motion-worker` | Python 动作规划、烘焙与质量检查；后续离线渲染和 FFmpeg 接线 |
| `infra` | Cloudflare 与后续数据、任务、重型服务的部署配置 |

Cloudflare 承载静态 Web 和轻量 API。Python 动作处理、渲染与 FFmpeg 使用独立重型执行环境，不硬塞进普通 Worker。后续依据真实耗时和费用评估 Cloudflare Containers 或外部 worker；保留规格的 PostgreSQL 默认选择，私有对象存储独立于 public 源码仓库。

每次交付先更新状态与限制，再执行相关检查并部署预览。阶段退出使用真实成果和可检查证据，不以测试数量替代动作、教师或发布验收。

## 已授权的 S0 工作台与 3D 场景基础

S0 version 4 已交付现代简洁的工作台及用户要求的 3D 场景基础；仍采用原创程序化人偶和 `preview-1`，不将此迭代视为 S1 完成。

- 突出骨骼并支持节点选择，清楚显示选中节点；选择不修改动作数据。
- 相机支持自由环绕、平移与缩放，提供侧面、俯视和复位视角。
- 坐标约定统一为右手系、Y 向上、+Z 正面、米单位与 XZ 地面；人偶、相机、网格和轴向指示遵循同一约定。
- 管理多个本机场景，保存对应音乐、播放状态、相机与视图设置；旧本地数据迁移后保留原音频和项目。浏览器数据清理仍会删除本地场景，没有服务器或跨设备同步。
- 验收覆盖场景切换/重开/删除、保存迁移与音频保留、视角和节点选择、坐标一致性、原编舞操作与小屏布局，再发布可核验版本。

该 S0 交付只包含节点选择和场景/视口基础。用户已授权继续实现实际手 K，进入下述 P1；S0 的旧验收不作为写帧功能的证据。

## P1 手动关键帧与骨骼编辑 · version 5 已交付

本轮不再停在关节选择，按 [手 K 设计](MANUAL_KEYFRAMES.md) 实现本地编辑扩展，并由 [#6](https://github.com/DFerryman/ChoreographyStudio/issues/6) 跟踪。CountMap 固定全场景时长，30 fps 整数键保留精确末帧；19 个关节保存父相对绝对 XYZW 旋转，Root XYZ 使用米单位，6 个末端只读。

姿态草稿先供即时预览，显式写入单轨或完整姿态后才成为权威动作。逐关节稀疏轨和独立 Root 轨以不可变基底播放：默认 0/结束边界为基底锚，显式端点键可覆盖，相邻关节键 SLERP、Root 线性插值。未编辑轨与旧 Scene 的精确 take 保持原样，不由 plan 重烘焙；正式修改产生新 take/revision 与共享历史，并随 Scene 保留轨道、基底和原音频。

用户可从站姿开始构建原创序列。模板采用须提示固化当前 motion 并清空可编辑轨，撤销可恢复；不能将旧轨再次套入新基底。未写草稿在跳帧、播放、切换、历史、生成与保存前须明确处理。

version 5 的删除 UI 只处理当前帧全部显式轨键，单轨删除当时仅供 core API 使用；下述 v7 接入独立关节/Root 删除 UI。4096 条轨键与输入/输出各 6001 个显式样本为独立资源上限，超限须拒绝，不把两者混作同一个额度。

退出条件为实际关节/Root编辑、写K/删除当前帧、连续插值、逐帧/播放、撤销与场景恢复可用，旧精确动画/音频和候选保护不退化，数值/资源边界与小屏可验证。上述本地范围、version5单轮7HTTP/完整线上14项与实际源码CI均通过，完成本轮P1退出条件；原内容、教师与生产里程碑保持未通过。

本轮没有 IK、骨长编辑、自动云保存、真实动作/Avatar 或教学 MP4；手 K、烘焙与保存仍在浏览器，不新增 D1 或业务 API 调用，沿用现有原生限频。

## 请求频率与写入预算

用户要求控制请求频率与数据库 rows written。S0/P1 继续在浏览器处理音乐、编排、手 K 与保存，公开 API 不接受音乐或项目写入；不引入 D1 写入来实现播放、关键帧、健康检查、轮询、日志或限频。

- 每次有意义的改动只做必要的单轮验收，不做循环生产测试或压测。相关源码、资产和行为未变时沿用已有验证证据。
- API 先有服务端限频；保护缺失或失败时拒绝受保护请求。当前 API 限频与后续数据库日写入额度分别记录，不把前者当作已上线的写入硬额度。
- Cloudflare 原生限频按节点生效且最终一致；按 IP 保护时，共享出口会共用额度，后续鉴权服务应使用账号身份。限频不是账户全局费用上限，429 和当前 inline 静态交付仍可能计 Worker 请求。
- 开放任何服务端写操作前，先实现业务幂等、批量/合并写入与明确的日写入预算门槛；预算触顶拒绝写入，轮询或自动重试不能产生额外写入。
- S2 保持 PostgreSQL 默认方案。若以后采用 D1，先记录 rows-written 预算、实际用量与门槛实现，再开放调用；不宣称尚未实现的 D1 硬额度或生产保护已上线。
