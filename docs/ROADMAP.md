## 原验收口径保持不变

- **M0｜素材与契约：**真实素材和权利证据、完整数据样例、命令边界与正反例；有真实可编排路径。
- **M1｜最小完整流程：**真实音乐到完整初稿、局部替换和教学视频；可播放、保存、导出，范围外不变，并有早期教师试跳。
- **M2｜教师验证：**留出任务及原流程/同库手选对照；采用、失败、返工、时间和成本有记录。
- **M3｜有限发布：**权限、版本、任务竞态、删除、回滚、设备与导出证据；内容与运行门槛同时通过。

R01 是协议与校验，R02 是真实小包，R03 是编排与烘焙，R04 是最小工作台，R05 是教学输出，R06 是教师试用与运行保护。R01/R02 并行；教师观察从首个可播放的真实组合开始，运行保护从接入服务开始。

## 仓库与部署

采用一个 public 仓库 `DFerryman/ChoreographyStudio`，用共享版本和测试避免首轮拆分仓库带来的契约漂移。

| 路径 | 职责 |
| --- | --- |
| `apps/web` | React/TypeScript 工作台与 3D 播放；消费 BakedTake |
| `packages/core` | 预览契约、数拍与版本规则、统一求值；S1 接入原契约 |
| `services/motion-worker` | Python 动作规划、烘焙与质量检查；后续离线渲染和 FFmpeg 接线 |
| `infra` | Cloudflare 与后续数据、任务、重型服务的部署配置 |

Cloudflare 承载静态 Web 和轻量 API。Python 动作处理、渲染与 FFmpeg 使用独立重型执行环境，不硬塞进普通 Worker。后续依据真实耗时和费用评估 Cloudflare Containers 或外部 worker；保留规格的 PostgreSQL 默认选择，私有对象存储独立于 public 源码仓库。

每次交付先更新状态与限制，再执行相关检查并部署预览。阶段退出使用真实成果和可检查证据，不以测试数量替代动作、教师或发布验收。

## 请求频率与写入预算

用户要求控制请求频率与数据库 rows written。S0/P1 继续在浏览器处理音乐、编排、手 K 与保存，公开 API 不接受音乐或项目写入；不引入 D1 写入来实现播放、关键帧、健康检查、轮询、日志或限频。

- 每次有意义的改动只做必要的单轮验收，不做循环生产测试或压测。相关源码、资产和行为未变时沿用已有验证证据。
- API 先有服务端限频；保护缺失或失败时拒绝受保护请求。当前 API 限频与后续数据库日写入额度分别记录，不把前者当作已上线的写入硬额度。
- Cloudflare 原生限频按节点生效且最终一致；按 IP 保护时，共享出口会共用额度，后续鉴权服务应使用账号身份。限频不是账户全局费用上限，429 和当前 inline 静态交付仍可能计 Worker 请求。
- 开放任何服务端写操作前，先实现业务幂等、批量/合并写入与明确的日写入预算门槛；预算触顶拒绝写入，轮询或自动重试不能产生额外写入。
- S2 保持 PostgreSQL 默认方案。若以后采用 D1，先记录 rows-written 预算、实际用量与门槛实现，再开放调用；不宣称尚未实现的 D1 硬额度或生产保护已上线。
