# 本机场景备份与恢复 · version 10

本轮补齐「下载 → 重新导入 → 继续编舞」的本机闭环。实现位于 `apps/web/src/sceneBackup.ts`，仍使用 `choreo-scene-1`、`preview-1` 和原创程序化骨架，读取、校验、音频解码与保存均在浏览器完成。107 项基础检查、最终构建/Worker 类型与 dry run、8 个不同本地范围经首轮/手机定向复核及缺失原音乐恢复相关单项通过；首次脚本与测试前环境启动问题及恢复保留。尚待公网/实际源码 CI 和发布，实际交付状态以 VERIFICATION.md / DEPLOYMENT.md 为准。

## 两种下载

| 入口 | 文件 | 包含什么 | 如何恢复 |
| --- | --- | --- | --- |
| 下载完整场景包 | `.choreo` | 原音乐字节、已写入的权威动作、CountMap、手 K 轨与不可变基底、场景历史和相机/观看设置 | 在「场景 → 导入场景备份」选择文件，验证后作为新场景导入 |
| 下载项目备份 | `choreo-studio-project.json` | 正式编舞和场景视图；沿用旧 `choreo-scene-backup-1`，`audioIncluded: false` | 在同一入口选择 JSON，然后重新关联备份时的原音乐 |

完整场景包导出前会处理未写 K 的姿态草稿：写入完整姿态后继续、放弃草稿后继续，或取消。导出开始时暂停播放，记录当时的实际播放位置，使用当前正式版本；导出本身不将场景标记为已保存，也不调用 IndexedDB 写入。旧 JSON 下载继续只导出正式数据，未写草稿和原音乐不包含在内，并明确提示。

两种文件均不保存临时姿态剪贴板、候选预览、待执行动作或未提交草稿。完整包包含原音乐，文件在本地生成并由浏览器下载，不上传服务器。

## 导入操作

1. 打开「场景」，点击「导入场景备份」。
2. 选择 `.choreo` 或旧 JSON。浏览器先检查格式、资源和动作关系；完整包另检查音频字节 SHA-256，并实际解码音乐。
3. 旧 JSON 没有音乐时，选择「重新关联原音乐」。程序核对解码时长及全部历史选段是否被音频覆盖；旧文件没有音频 hash，时长相同也不能证明曲目相同，界面要求用户确认选择的是备份时的曲目。
4. 检查场景名称和音乐信息，点击「作为新场景导入」。如当前作品有草稿或未保存修改，沿用现有写入/放弃/取消和保存后继续保护。

导入重新生成场景 ID 和创建时间，保留当前已保存场景。新场景、原音乐、索引和当前场景标记通过同一次 IndexedDB 事务保存；只有事务完成后才切换到导入场景。格式、音乐或存储失败时报告错误，取消或失败均不覆盖当前打开的作品。关闭导入后，过时的文件读取/解码结果不会重新应用。

导入保留正式项目的历史、当前历史位置、作品 revision、CountMap ID、plan/take ID、原始显式采样时刻与姿态、手 K 基底和轨道、相机及观看设置。它不会重新确认音乐、从 plan 重新生成动作或把旧轨再次套到新基底。`teacherCheckedRevision` 清空为 `null`，不从备份带入教师确认；新场景应用时也清除剪贴板、候选和草稿。没有可选工具字段的旧场景仍按既有兼容规则打开。

## 恢复已保存场景缺失的原音乐

本机场景记录若没有原音频，仍显示并保留正式编舞与 CountMap；播放器源清空，不悄然使用示例音乐。播放、保存和「下载完整场景包」禁用，数据仍可通过「下载项目备份」保留。这个分支已通过相关本地复核，包括时长不符拒绝、恢复前写 K 后保留最新正式项目，以及原缺音乐场景不覆盖。

点击「原音乐缺失」提示中的「恢复原音乐」，在现有恢复对话框选择备份时的原曲。实际解码需符合 16–600 秒、100 MiB 和时长/历史选段覆盖规则；这里只核对时长和覆盖，用户仍需确认曲目。可以修改恢复后的名称，然后「作为新场景导入」。

恢复请求固定当前场景和 CountMap，继续保留草稿及未保存场景的处理。用户选择先写完整姿态时，恢复捕获处理后的最新正式项目、K/历史和当前相机视图，而非对话框打开时的旧预览；不丢弃这次明确写入。新 ID、清空教师确认的场景与所关联原音乐在事务成功后应用，旧场景及其 `audio: null` 保持原样。恢复不是重新导入音乐重建动作，不能调用确认音乐、清轨或由 plan 重烘焙；错误和取消仍保留当前作品。

## `.choreo` 文件格式

文件是有界二进制容器，按以下顺序直接拼接，不是 ZIP：

| 部分 | 内容 |
| --- | --- |
| 标记 | UTF-8 字节 `CHOREO-BUNDLE-1`，末尾一个换行，共 16 字节 |
| 长度 | 4 字节无符号小端整数，表示后续 JSON 头的字节长度 |
| JSON 头 | UTF-8 对象 `{ format, scene, audio }`；`format` 为 `choreo-scene-bundle-1`，`scene` 不含 `audio` 字段 |
| 音频 | 原 Blob 的完整二进制字节，未经重新编码 |

JSON 头中的 `audio` 包含 `byteLength`、`mimeType`、`sha256`。SHA-256 为原音频字节的 64 位小写十六进制摘要；解析时核对它与文件尾音乐一致，并核对总长度精确等于前缀、JSON 头和声明音频长度之和。截断、追加数据或摘要不一致拒绝导入。摘要用于完整性检查，不代表曲目身份、教师验收或版权证明。

MIME 元数据允许安全的 `audio/*` 子类型（含 `audio/x-m4a` 等厂商变体）及 `application/octet-stream`；原 Blob 没有类型时使用后者。元数据允许不等于浏览器支持播放，最终仍须 `AudioContext.decodeAudioData` 解码通过。

旧 JSON 严格接受 `format: choreo-scene-backup-1`、`audioIncluded: false` 和受支持的 `scene`。它不能内嵌音乐，必须重新关联原音频，不能悄然补入示例音乐。

## 校验与资源限制

| 资源 | 上限或范围 |
| --- | --- |
| JSON 头、旧 JSON 文件 | 32 MiB |
| 原音乐 | 非空，最多 100 MiB；实际解码 16–600 秒 |
| 完整包 | 132 MiB 加 20 字节固定前缀 |
| 场景历史 | 1–12 条，当前历史索引须有效 |
| 全场景显式样本 | 最多 150,000；累计所有历史条目的权威 take 与 `manual.baseTake`，分别计数 |
| 单个 take / 手 K 基底 | 2–6,001 个样本，时间和姿态数量相同 |
| 单个手 K 序列 | 最多 4,096 条关节/Root 轨键，30 fps 合法整数帧 |
| JSON 嵌套 | 最多 32 层；拒绝重复字段和原型相关危险字段 |

先检查文件及声明头长度，再读取相应区域，避免无界分配。解析使用严格 UTF-8；未知字段、版本、角色或坐标协议拒绝导入。场景必须是当前原创 25 关节骨架，右手系、Y 向上、+Z 前向、米单位和 XZ 地面。所有数字必须有限，四元数为单位 XYZW；每条轨的键严格递增、不重复，只允许 19 个可编辑旋转与独立 Root 轨。

CountMap 校验速度、音乐拍关系、完整八拍起点/时长、数拍时间和音频覆盖；plan、take 和 manual 的 ID、时长、来源及数拍绑定须一致。单个 take 必须严格递增且包含精确 0 和结束时刻。有效的旧稀疏 take 可以原样恢复，不要求凭空插入八拍边界或重烘焙 plan。源 take 的有限 Root 坐标也原样保留，不因当前编辑范围而裁剪；显式 Root 轨键继续限制 X/Z ±5 米、Y 0–3 米。

手 K 校验还会按当前核心规则计算预期产物，逐一比对基底与键时刻集合、插值后的 Root 和关节旋转；四元数 q 与 −q 视为相同旋转。校验用于确认保存的权威 take 和手 K 轨一致，成功后保留导入的原始 take 数据，不用临时计算结果替换它。

实际音乐解码时长与项目记录相差不能超过 0.1 秒，全部历史选段都必须被解码音频覆盖。完整包的 hash 加解码检查能够发现损坏或无法播放的音乐；旧 JSON 重新关联仅核对时长和覆盖，用户仍需确认曲目。

## 交付边界

场景包不是 MP4 或经过验收的教学导出，不接入模型、云存储、服务器音乐上传或 D1。浏览器清理仍会删除本机 IndexedDB；下载完整包可以保留一个可导入的副本，但不会提供自动同步。

测试优先验证精确数据和音频恢复、损坏/资源/协议拒绝、草稿与场景切换保护、事务失败和窄屏操作。本轮完成相关本地、必要单轮线上、真实源码 CI、GitHub push 和对应 Cloudflare 发布后，再更新验收与部署记录；原创音频与骨架测试不替代真实素材授权、原工程契约、设备音画或教师验收。
